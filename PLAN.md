# План SSTP VPN-клиента для Windows

Дата: 2026-09-12. Статус: проект функциональности; реализация и сетевые испытания ещё не выполнены.

## 1. Цель и исходные условия

Создать настольное приложение с русским интерфейсом, которое подключается к SSTP VPN-серверу и автоматически разделяет исходящий трафик компьютера:

- российские IP-адреса — через выбранное основное подключение;
- остальные публичные IP-адреса, включая неизвестные базе, — через VPN;
- локальная сеть — напрямую, если пользователь разрешил доступ;
- отдельные адреса и подсети — по пользовательским исключениям.

Целевая среда — текущий компьютер пользователя. Проверено локально 2026-09-12: Windows 11 Pro x64, версия 10.0.26200, сборка 26200; AMD Ryzen 9 5900X, около 32 ГБ RAM. Физический адаптер «Беспроводная сеть» (Intel Wi-Fi 6 AX200) активен; Ethernet (Intel I211) и Ethernet 2 (Realtek 2.5GbE) на момент проверки отключены. Службы RasMan, SstpSvc и BFE установлены и запущены. Это подтверждает наличие системных компонентов, но не проверку SSTP-подключения или маршрутизации.

Первую сборку и приёмку ориентировать на эту Windows и её сетевое окружение. Поставка — установщик x64 с необходимым runtime приложения, чтобы пользователю не требовалось устанавливать SDK. Интерфейс и служба выполняются локально на этом компьютере; для обычной работы используются VPN-сервер и источники обновлений базы. Основной адаптер выбирается по фактическому маршруту при запуске, а не жёстко закрепляется за текущим именем Wi-Fi.

Остальные допущения: один активный SSTP-туннель, существующий SSTP-сервер с выходом в интернет. Приложение работает для трафика самого компьютера. Настройка сервера, раздача VPN другим устройствам и одновременное распределение нагрузки между несколькими туннелями в первую версию не входят. Поддержка других версий Windows и ARM64 требует отдельной матрицы совместимости.

«Российский» означает страну IP-адреса назначения по выбранной базе геолокации. Это не гражданство владельца сервиса, не язык страницы и не доменная зона. Российский сайт с зарубежным хостингом пойдёт через VPN; зарубежный сервис с российским узлом CDN — напрямую. Геолокация имеет погрешности. Ручные исключения позволят корректировать результат.

Клиент не создаёт зарубежную точку выхода сам: расположение выходного IP определяется выбранным VPN-сервером.

## 2. Подход к реализации

Использовать встроенный SSTP Windows через RAS API, собственную службу управления маршрутами и настольный интерфейс. Windows предоставляет API установления RAS-соединения и изменения IP-маршрутов. Это позволяет опереться на системную реализацию SSTP. [RAS API](https://learn.microsoft.com/en-us/windows/win32/api/ras/nf-ras-rasdialw), [IP Helper API](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-createipforwardentry2).

Для российского списка создавать более специфичные маршруты через основное подключение; остальные публичные назначения направлять маршрутом по умолчанию в VPN. Общая модель основана на системной таблице маршрутов Windows. [Маршрутизация Windows VPN](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/vpn/vpn-routing).

Защиту от обхода VPN строить отдельно, на Windows Filtering Platform (WFP). Маршруты выбирают путь, фильтры запрещают недопустимый выход. Возможности постоянных и загрузочных фильтров есть в WFP, но конкретную схему необходимо подтвердить прототипом и сетевыми испытаниями. [Работа WFP](https://learn.microsoft.com/en-us/windows/win32/fwp/basic-operation).

## 3. Подключения и профили

Профиль содержит:

- название и адрес SSTP-сервера;
- имя пользователя, необязательный домен и выбранный поддерживаемый сервером способ аутентификации;
- настройку сохранения учётных данных;
- основное сетевое подключение: автоматический выбор либо конкретный Ethernet/Wi-Fi адаптер;
- режим маршрутизации, DNS, IPv6 и поведение при обрыве;
- параметры автоматического подключения и повторных попыток.

Действия: создать, изменить, копировать, удалить, проверить, подключить, отключить. Можно хранить несколько профилей, активен один. Импорт и экспорт настроек — в версионируемый JSON без паролей и закрытых ключей.

Проверка профиля различает ошибки разрешения имени, недоступность сервера, ошибку сертификата, отказ аутентификации, отсутствие интернета в туннеле и ошибку применения маршрутов. Успешная проверка TCP сама по себе не означает работоспособность SSTP.

Сертификат сервера проверяется штатными механизмами Windows: доверенная цепочка, имя и срок действия. Кнопку отключения проверки сертификата не предусматривать. Для частного центра сертификации — инструкция по доверенной установке сертификата. Конкретные методы EAP и сертификатной аутентификации выбирать после проверки сервера; первая реализация покрывает его фактическую конфигурацию.

Пароли не передаются аргументами командной строки и не попадают в настройки или журнал. Использовать защищённое хранилище Windows; доступ службы к секретам и связь профиля с пользователем проверить отдельно. Без сохранения пароля автоматическое подключение после перезапуска может требовать ввода.

## 4. Правила маршрутизации

### Режимы

| Режим | Российские адреса | Остальные публичные адреса |
| --- | --- | --- |
| Россия напрямую — основной | Основное подключение | VPN |
| Весь интернет через VPN | VPN | VPN |
| VPN отключён | Обычная сеть либо сохранённая защита — зависит от явного действия пользователя | То же |

Локальная сеть и служебные исключения обрабатываются отдельно. При активной защите и недоступном VPN адреса, назначенные VPN, блокируются.

### Выбор интерфейсов

- Автоматический режим выбирает доступное основное подключение до применения VPN-маршрутов и отслеживает смену шлюза.
- Ручной режим закрепляет конкретный адаптер; при его исчезновении переход на другой разрешается только отдельной настройкой.
- В расширенных настройках можно выбрать другой физический адаптер для транспорта SSTP: например, Россия через Ethernet, SSTP через Wi-Fi. Этот сценарий входит после проверки базового варианта на одном адаптере.
- Идентификация адаптеров должна переживать смену индекса интерфейса. В UI показываются понятное имя, тип и доступность.
- При смене сети туннель может переподключаться, а существующие TCP-сеансы — прерываться; бесшовная миграция соединений не обещается.

### Порядок применения политики

1. Обязательные служебные исключения: транспорт к VPN-серверу, минимальные операции начального DNS-разрешения и обслуживания сети. Показывать их отдельно.
2. Ограничения доступа к локальной сети и специальные адреса: loopback, сеть самого адаптера (on-link), link-local, multicast, широковещание.
3. Пользовательские правила IP/CIDR: напрямую, через VPN, блокировать. Правило перекрывает частные сети (10/8, 172.16/12, 192.168/16, 100.64/10) — так в туннель направляется удалённая частная сеть; без правила частная сеть остаётся локальной.
4. База российских сетей: напрямую.
5. Остальные публичные назначения: VPN.

Для пересекающихся пользовательских правил побеждает более конкретная подсеть; противоречащие правила одинакового префикса запрещены. Пользовательские исключения имеют приоритет над геобазой. Широкое пользовательское правило «через VPN» должно исключать вложенные российские сети из прямого списка: одними метриками маршрутов этот приоритет не обеспечить. Перед применением компилятор политики формирует согласованные диапазоны для маршрутов и фильтров.

Нельзя перенаправить транспорт самого VPN внутрь его туннеля. Для всех актуальных IP SSTP-сервера создавать адресные маршруты через транспортный адаптер; учитывать повторное DNS-разрешение и IPv4/IPv6.

Специальные диапазоны не классифицировать по стране. Loopback сохраняется локальным; DHCP, ARP, IPv6 ND и другие необходимые операции работают по минимальной политике. Доступ к локальным устройствам и multicast управляется отдельно. Чужие корпоративные маршруты проверяются на конфликт, а не молча перезаписываются.

### База российских адресов

- Локальный версионируемый список IPv4/IPv6 CIDR с источником, датой и количеством диапазонов.
- Для географической страны — поле страны расположения IP в GeoIP-источнике. Регистрационный country-код выделения сети не считать эквивалентом геолокации.
- Предлагаемый источник первой версии — готовый RU CIDR-список Loyalsoldier/geoip; альтернативы — GeoLite Country напрямую и DB-IP Lite. IPdeny/ipverse доступны как отдельный режим определения страны по регистрации сети. Результаты исследования, ссылки, ограничения и проверка скачивания: [готовые проекты и базы](RESEARCH.md).
- Автоматическое скачивание обязательно: при первом запуске и затем проверка раз в 24 часа, после восстановления сети при пропущенном сроке, а также вручную. Частота проверки приложения не равна частоте выпуска базы поставщиком. Проверять формат, происхождение, контрольную сумму и аномальное изменение состава. Полный порядок обновления и настройки описаны в [исследовании](RESEARCH.md#автоматическое-скачивание-в-приложении).
- Подписанный манифест при распространении базы собственным каналом; одна контрольная сумма не подтверждает подлинность.
- Обновление в фоновом режиме: сначала загрузить и проверить, затем применить согласованную версию. Сохранить последнюю рабочую базу и возможность отката.
- Сбой обновления не ломает подключение. Возраст базы показывается пользователю.
- При отсутствии первой базы не включать разделение молча: предложить загрузку или режим всего интернета через VPN.
- Объединять только точно смежные совместимые диапазоны, не расширяя список России ради уменьшения количества маршрутов.

## 5. DNS, IPv6 и защита при сбоях

### DNS

В первой версии обычные системные DNS-запросы обслуживаются локальным DNS-посредником с upstream через VPN. DNS-обмен является явно выделенным служебным трафиком; IP-трафик к полученному адресу затем маршрутизируется по общей политике. Состояние системных DNS-настроек сохраняется для корректного восстановления.

До установления туннеля требуется разрешить имя SSTP-сервера. Предусмотреть отдельный минимальный механизм начального разрешения, кеш адресов и явно описанное исключение к выбранному DNS-серверу. Проверка сертификатов также может потребовать доступа к инфраструктуре CA: состав необходимых исключений определить на прототипе, не отключая проверку отзыва ради подключения.

При обрыве VPN посредник не переключается незаметно на DNS провайдера. Для прямых российских ресурсов доступны кешированные записи; новые имена могут не разрешиться. Дополнительный режим «DNS напрямую при обрыве» явно сообщает, что провайдер увидит запросы, и включается пользователем.

Доступ к локальным именам — отдельная опция с заданными локальными суффиксами и DNS. В первой версии публичные доменные исключения не обещаются: CDN, общие IP и собственный DoH приложений требуют отдельной разработки. Приложение с собственным DNS/DoH по-прежнему подчиняется IP-маршрутам, но его запросы нельзя считать обработанными нашим посредником. UI не должен заявлять полный контроль над зашифрованным DNS сторонних приложений.

### IPv6

- Проверять IPv6 как самостоятельный путь, включая адреса VPN-сервера и DNS.
- При полноценной поддержке сервером применять ту же политику разделения к IPv6.
- В первой версии при отсутствии проверенного IPv6 в VPN блокировать публичный IPv6 на время защиты и показывать «IPv6 ограничен». Локальные необходимые механизмы IPv6 сохраняются.
- Сервисы только с IPv6 могут стать недоступны. Для полного выполнения требования по обоим семействам адресов нужны SSTP-сервер с IPv6 и отдельные успешные испытания.
- Не отключать IPv6 глобально через реестр и не оставлять зарубежный IPv6 бесконтрольно выходить напрямую.

### Защита при обрыве (kill switch)

Рекомендуемый режим: адреса, которым предписан VPN, запрещены на физических интерфейсах даже во время переподключения. Российские адреса и разрешённая локальная сеть остаются доступны напрямую с указанным выше ограничением DNS. Ручное правило «через VPN» защищается независимо от страны адреса.

Варианты настроек:

- блокировать только трафик, назначенный VPN — по умолчанию;
- при обрыве блокировать весь публичный интернет;
- разрешить весь трафик напрямую при обрыве — с явным указанием последствия.

Закрытие окна оставляет службу и туннель работающими. В трее доступны отдельные действия «Отключить VPN, сохранить защиту» и «Отключить VPN и восстановить обычный интернет». Состояние блокировки должно быть видно без открытия настроек.

Защита проверяется при принудительном завершении UI и службы, падении SSTP, смене сети, сне и перезагрузке. Динамические фильтры, исчезающие при падении службы, недостаточны для режима постоянной защиты. Для защиты с загрузки Windows нужен отдельно проверенный набор постоянных и загрузочных фильтров. [Время жизни объектов WFP](https://learn.microsoft.com/en-us/windows/win32/fwp/object-management).

Предусмотреть журнал собственных системных изменений, восстановление после частично выполненной операции и административную команду аварийного восстановления сети. Восстанавливать только изменения приложения, учитывая последующие изменения пользователя и DHCP.

## 6. Пользовательский интерфейс

Стиль: русские подписи, светлая и тёмная темы, корректное масштабирование, управление с клавиатуры, доступные контрасты и текстовые статусы вместо индикации только цветом. Сложные настройки скрыты в расширенном разделе.

| Экран | Содержание и действия |
| --- | --- |
| Первый запуск | Адрес сервера и вход → выбор основной сети → режим разделения → загрузка базы → проверка подключения |
| Главная | Большая кнопка подключения, профиль, статус защиты, режим, основное подключение, VPN-адрес, длительность сеанса, предупреждения с действием |
| Подключения | Список профилей, редактирование, проверка сервера, копирование, импорт/экспорт |
| Маршрутизация | Режим, выбранные адаптеры, IPv4/IPv6, дата базы, пользовательские IP/CIDR-исключения, поиск и объяснение конфликтов |
| Проверить адрес | Ввод IP или домена; все полученные A/AAAA, страна, источник решения, ожидаемый интерфейс, фактический маршрут и возможная блокировка |
| Защита и DNS | Поведение при обрыве, DNS, локальная сеть, IPv6, защита после перезагрузки |
| Настройки | Автозапуск, автоподключение, повторные попытки, тема, уведомления, обновления, экспорт настроек |
| Диагностика | События подключения и маршрутов, понятные ошибки с системным кодом, состояние службы, безопасный экспорт отчёта, восстановление сети |

Главный экран должен отвечать на три вопроса: подключён ли VPN; куда идут российские и остальные адреса; защищён ли трафик сейчас. Пример статуса: «Россия → Ethernet · Остальные адреса → VPN · Защита включена».

Состояния: отключено, подготовка защиты, подключение, применение маршрутов, подключено, переподключение, трафик заблокирован, ошибка. «Подключено» показывать только после готовности туннеля, DNS и политики.

В трее: текущий статус, подключить/отключить, сменить профиль, открыть приложение. Уведомления — при значимых сбоях и восстановлении, без повторения каждой попытки.

Статистика первой версии: скорость и объём VPN-сеанса, состояние физического подключения. Счётчики физического адаптера содержат и SSTP-транспорт, поэтому их нельзя подписывать как объём российского трафика. Точный раздельный учёт прямого и туннельного трафика — отдельный этап с измерением накладных расходов.

Проверка домена диагностическая: она не создаёт постоянного правила. При CDN разные адреса одного домена могут идти разными путями. Проверка внешнего IP по двум путям требует реально привязанных диагностических соединений и явно выбранного проверочного сервиса; обычный запрос через текущий маршрут недостаточен.

## 7. Архитектура и хранение

Предлагаемый стек: C# на поддерживаемой LTS-версии .NET, WPF и MVVM для Windows-интерфейса, Windows Service для системных операций, Win32 interop для RAS, IP Helper и WFP. WPF предназначен для настольных приложений Windows. [Обзор WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/), [Политика поддержки .NET](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).

Компоненты:

- UI — ввод настроек и отображение состояния, без постоянного запуска от администратора.
- Service — единый координатор состояния, контроль активного профиля, восстановление после сбоя.
- RAS adapter — профиль SSTP, подключение, отключение, события и коды ошибок.
- Policy compiler — единая модель адресных правил для маршрутов, фильтров и диагностики.
- Routing manager — таблицы IPv4/IPv6, интерфейсы, шлюзы, изменения сети и проверка результата.
- Protection manager — WFP-провайдер, фильтры, состояния защиты и восстановление.
- DNS proxy — системные запросы, upstream, кеш и ограниченное начальное разрешение.
- Geo data manager — загрузка, валидация, версии и обновления базы.
- Diagnostics — структурированные журналы, проверки и отчёт без секретов.

UI общается со службой через локальный IPC с ACL и проверкой личности вызывающего пользователя. Служба принимает только типизированные проверенные команды, не произвольные команды оболочки. Для первого выпуска один локальный администратор управляет общей сетевой политикой; поведение при нескольких Windows-пользователях явно ограничено и проверяется.

Настройки — версионируемый JSON; база маршрутов — отдельные данные; секреты — защищённое хранилище Windows; журналы — с ротацией и ограничением срока хранения. Историю посещённых доменов по умолчанию не вести. Диагностический экспорт предлагает скрыть имя пользователя, сервер и адреса сети.

Собственный драйвер в базовую архитектуру не закладывать. Если прототип покажет, что выбранные гарантии защиты невозможно обеспечить стандартными фильтрами, сначала пересмотреть схему или явно расширить объём работ.

## 8. Последовательность подключения и восстановления

1. Проверить профиль, базу, доступность службы, адаптеры и конфликты с другими VPN.
2. Сохранить состояние затрагиваемых настроек и начать журнал операции.
3. Подготовить защиту и необходимые служебные исключения.
4. Разрешить имя сервера и закрепить его транспорт через выбранный адаптер.
5. Установить SSTP, получить фактические параметры VPN-интерфейса и DNS.
6. Применить согласованную адресную политику, настроить DNS и проверить маршруты.
7. Проверить выход через VPN и прямой маршрут; только после этого показать готовность.
8. Отслеживать RAS, интерфейсы, DNS и изменения таблицы маршрутов; при несоответствии переходить в защищённое состояние и восстанавливать конфигурацию.

Для обновления маршрутов и фильтров нет общей системной транзакции: применять изменения поэтапно под защитой, с контролем результата. При ошибке откатывать собственные изменения до согласованного состояния. Неполный откат показывается как ошибка с доступным восстановлением сети.

Повторные подключения — с увеличением задержки и небольшим случайным разбросом. Ошибку неверного пароля или сертификата не превращать в бесконечный цикл. После сна и смены шлюза заново проверять сеть и актуальность адресов сервера.

## 9. Этапы разработки и результаты

| Этап | Работа | Критерий завершения |
| --- | --- | --- |
| 1. Уточнение окружения | Текущая Windows 11 Pro x64, сборка 26200, проверена; уточнить SSTP-сервер, вход, сертификаты, DNS/IPv6 и источник базы | Зафиксирован тестовый профиль и матрица поддержки текущего компьютера |
| 2. Сетевой прототип | Изучение MIT-кода VpnDialerPlus, RAS, прямые RU-маршруты, VPN по умолчанию, транспортные исключения, WFP, DNS, скачивание реальной базы | На стенде подтверждены два пути и блокировка обхода; измерена полная база, принято решение о целесообразности sing-box |
| 3. Служба и политика | Состояния, правила, версии базы, наблюдение сети, журнал изменений, восстановление | Повторное применение безопасно; после частичных сбоев состояние восстанавливается |
| 4. Интерфейс | Мастер, главная, профили, настройки, правила, трей, диагностика | Основной сценарий выполняется без командной строки |
| 5. Полная первая версия | Обновление базы, импорт/экспорт, автостарт, IPv6-политика, сообщения об ошибках | Все обязательные сценарии доступны и отражают фактическое состояние |
| 6. Системные испытания | Утечки, обрывы, сон, смена сети, масштаб базы, другие сетевые приложения | Пройдена матрица приёмки, ограничения документированы |
| 7. Поставка | Установщик, служба, удаление, обновление, инструкция восстановления | Чистая установка/обновление/удаление проверены в VM; подготовлены исходники и сборка |

Первым техническим результатом должен стать прототип с доказанной маршрутизацией и защитой. Красивый интерфейс поверх неподтверждённой сетевой схемы не считается готовым клиентом.

Для распространения предусмотреть подпись установщика и исполняемых файлов; сертификат подписи и инфраструктура обновлений — отдельные ресурсы проекта. Обновления не должны создавать окно снятой защиты. Первая поставка может использовать ручное обновление подписанным установщиком.

Точные сроки определяются после этапа 2: основные неопределённости — совместимость сервера, фильтрация IPv6/DNS и поведение на полном объёме маршрутов. Сетевой прототип не равен готовому продукту.

## 10. Проверки и критерии приёмки

| Сценарий | Ожидаемый результат |
| --- | --- |
| Адрес из RU-базы | Прямой выход через выбранное основное подключение |
| Иностранный или неизвестный публичный адрес | Выход через VPN |
| Ручное исключение и пересечение подсетей | Результат соответствует приоритетам; диагностика объясняет правило |
| SSTP-сервер с несколькими адресами | Транспорт не попадает внутрь туннеля; переподключение работает |
| TCP, UDP/QUIC, ICMP и уже открытые соединения | Не обходят требуемый путь, либо блокируются согласно политике |
| Обрыв VPN | Запрещённый прямой выход отсутствует; UI показывает защиту |
| IPv6 при IPv4-only VPN | Публичный IPv6 блокируется, состояние явно показано |
| DNS | Нет незаявленного переключения системных запросов на DNS провайдера |
| Падение UI/службы, сон, перезагрузка | Сохраняется выбранная гарантия защиты; возможно управляемое восстановление |
| Переключение Ethernet/Wi-Fi и смена DHCP-шлюза | Маршруты обновляются без незаметного обхода VPN |
| Локальные устройства и локальный DNS | Работают только в соответствии с настройкой локального доступа |
| Плохая или недоступная новая GeoIP-база | Используется последняя рабочая версия; видна причина отказа |
| Конфликт с другим VPN или защитным ПО | Ошибка или диагностируемое ограничение, без молчаливой порчи чужой настройки |
| Удаление приложения | Собственные профили, маршруты, DNS-изменения и фильтры корректно убраны |

Методы: модульные проверки приоритетов/CIDR и состояний; интеграционные испытания Windows-службы; VM со снимками; реальный SSTP-сервер; захват пакетов на физическом и VPN-интерфейсах и по возможности на шлюзе. После испытаний сбоев и восстановления в VM выполнить итоговую проверку на текущем компьютере пользователя, включая его Wi-Fi-адаптер. На физическом интерфейсе SSTP-транспорт ожидаем; проверяется отсутствие прямых пакетов к назначениям, обязанным идти через VPN.

Проверять всю используемую RU-базу, пиковое число правил, время подключения и обновления, CPU/RAM, DNS-задержку, пропускную способность и отзывчивость UI. Числовые пороги зафиксировать после измерений прототипа на целевом оборудовании, а не выдавать предположения за гарантии.

Первая версия готова, когда пользователь устанавливает приложение, вводит параметры сервера, включает разделение одной кнопкой, видит фактическое состояние, может добавить IP-исключение и восстановить сеть, а сетевые тесты подтверждают выбранную политику при нормальной работе и сбоях.

## 11. Возможности после первой версии

- Автоматический выбор резервного SSTP-сервера и несколько транспортных интерфейсов.
- Дополнительные группы стран, расписания и профили для разных сетей.
- Поддержка дополнительных Windows-архитектур и серверных способов аутентификации.

## 12. Что уточнить перед реализацией

- Целевая ОС уже определена: текущая Windows 11 Pro x64, сборка 26200. Перед итоговой приёмкой повторно проверить сборку на случай обновления Windows.
- Уже существующий SSTP-сервер, его ПО, способ входа, DNS и наличие IPv6. Секреты вводятся в клиенте, не фиксируются в плане.
- Достаточно ли определения России по IP-геолокации; нужны ли обязательные исключения для конкретных сервисов.
- Должна ли защита сохраняться с загрузки компьютера и при ручном отключении VPN.
- Требуется ли разный физический адаптер для прямого трафика и транспорта SSTP уже в первом выпуске.
- Приложение только для личного использования или для распространения: это влияет на лицензирование базы и поставку обновлений.

Эти вопросы не мешают согласовать функциональную модель. Рабочие значения по умолчанию: Windows 11 x64, один активный профиль, Россия по GeoIP, остальные адреса через VPN, защита трафика VPN при обрыве, автоматический выбор основного адаптера, ручные IP/CIDR-исключения.
