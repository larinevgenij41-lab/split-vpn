# Проверки поддержки VPN-протоколов

Дата: 2026-09-13. Ветка: `codex/vpn-protocols`. Версия: 0.2.0.

## Подтверждено локально

- .NET Release-сборка решения без предупреждений.
- 226 тестов: ядро, служба на фейках и 28 сочетаний протокола/входа через настоящий Windows RAS API.
- Собран `artifacts/installer/SplitVpn-0.2.0.msi` (57 714 396 байт); база MSI открыта
  через Windows Installer в режиме чтения, `ProductVersion` — `0.2.0`.
  SHA256: `D1B0D9276DFC6DE08A4B3C479A1F13F80F36005F0A619BE81CE56937A916956E`.
- `RasSetEntryProperties`/`RasGetEntryProperties`: создание и чтение отдельной временной телефонной книги
  с нужной VPN strategy для SSTP/L2TP/IKEv2/PPTP. После теста записи и временная папка удаляются.
- EAPHost принимает конфигурации и тестовые учётные данные EAP-MSCHAPv2, PEAP-MSCHAPv2,
  EAP-TLS, TTLS/MSCHAPv2 и TTLS/PAP. Конфигурация записывается через `RasSetCustomAuthData`.
- Миграция схемы 1 → 2, запрет несовместимых способов входа и портов, маскирование секретов,
  необходимость PSK, смена протокола при неизменном сервере, передача новых секретов до дозвона,
  отсутствие требования пароля для машинного сертификата, отказ старому IPC-клиенту.
- Модель WFP: разрешения выбранного транспорта только к VPN-серверу через основной адаптер,
  запрет этих исключений для другого сервера/адаптера и удаление SSTP-порта при смене на IKEv2.
- Изолированная проверка WPF без запуска основной программы и без команд службе:
  четыре протокола, обновление допустимых методов (для IKEv2 — шесть), загрузка шаблона безопасности.
  Снимок: `artifacts/ui-protocol-probe/security.png`.

## Особенности Windows, найденные при проверке

- У TTLS CA-хеш в XML принимается с пробелами между байтами: непрерывная hex-строка дала 1465.
  В генераторе используется формат `AA BB ...`; результат проверен нативным преобразованием.
- В `EapTtlsUserPropertiesV1` реально работает элемент `EapTtls` с заглавной E.
  Локальная XSD содержит `eapTtls`, но этот вариант API отверг с 0xE225.
  Заглавный вариант принят для обоих внутренних методов, с получением BLOB учётных данных.
- Для PAP в TTLS элемент `PAPAuthentication` пустой; `UseWinlogonCredentials` допустим внутри
  `MSCHAPv2Authentication`, но не внутри PAP.
- Буфер EAP-данных закрепляется в памяти на весь асинхронный RasDial, затем очищается вызывающим кодом.
- Проекция IKEv2 читается по типу объединения, отдельно от PPP; предусмотрен повтор с увеличенным буфером.

## Не проверено выполнением

- Успешные соединения новых протоколов и EAP-методов с реальными серверами.
- PSK через `RasSetCredentials` от LocalSystem: текущий процесс тестов не повышен;
  положительная проверка защищённого хранилища RAS требует административного контекста.
- Реальный выбор сертификата/доступ к закрытому ключу от LocalSystem, включая EAP-TLS без пользователя.
- WFP на новых транспортах с сетевым захватом: ALE/IPsec, ESP, GRE, NAT-T и отсутствие утечек при обрыве.
- Сон/возобновление, перезапуск службы в реальном соединении новых протоколов.
- Установка обновления и откат. Рабочая служба, текущий VPN и сетевые настройки не изменялись.

Для завершения сетевой приёмки нужны тестовые серверы и сертификаты из этапа 7
[согласованного плана](VPN-PROTOCOLS-PLAN.md). Эти ограничения не подменяются результатами фейков.
