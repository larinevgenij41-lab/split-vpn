# Протоколы и способы входа (0.2.0)

Приложение использует встроенные Windows RAS и EAPHost. Протокол и способ входа выбираются
в «Подключениях» и мастере первого запуска. Шифрованием транспорта управляет Windows;
настройки глобальных криптографических политик приложение не меняет.
Исключение — Cisco AnyConnect (с 0.3.0): он работает через libopenconnect, см. [раздел ниже](#cisco-anyconnect).

## Поддерживаемые сочетания

| Протокол | Способы входа |
|---|---|
| SSTP | MS-CHAPv2, EAP-MSCHAPv2, PEAP/EAP-MSCHAPv2, EAP-TLS, EAP-TTLS/MSCHAPv2, EAP-TTLS/PAP, PAP, CHAP |
| L2TP/IPsec | Те же способы входа; отдельно выбирается PSK или сертификат компьютера для IPsec |
| IKEv2 | EAP-MSCHAPv2, PEAP/EAP-MSCHAPv2, EAP-TLS, EAP-TTLS/MSCHAPv2, EAP-TTLS/PAP, сертификат компьютера |
| PPTP | MS-CHAPv2, EAP-MSCHAPv2, PEAP/EAP-MSCHAPv2, EAP-TLS, EAP-TTLS/MSCHAPv2, EAP-TTLS/PAP |

PPTP оставлен для совместимости, с обязательным MPPE. PAP/CHAP в PPTP и обычный
PPP MS-CHAPv2 в IKEv2 запрещены валидатором. Автоматического перехода между протоколами нет.
PAP/CHAP доступны только внутри SSTP или L2TP/IPsec: у них нет собственных MPPE-ключей,
шифрование обеспечивает транспорт TLS/IPsec. Внутренний PAP в TTLS защищён TLS-туннелем TTLS.

SSTP принимает `vpn.example.org` или `vpn.example.org:4443`. Остальные протоколы принимают
имя сервера или IPv4 **без порта**. Для IKEv2 используйте имя, соответствующее сертификату сервера.

## Пароли и ключ IPsec

Логин, пароль и необязательный домен задаются для способов входа по паролю. Для L2TP/IPsec
с PSK дополнительно нужен общий ключ сервера. «Сохранять пароль» относится к паролю пользователя;
PSK сохраняется отдельно через DPAPI с доступом только SYSTEM/Administrators.

Пустое поле в редакторе означает «не менять». Для удаления PSK есть отдельный флажок.
При смене способа входа старый пароль удаляется — введите пароль для нового способа заново.
При удалении профиля удаляются его секреты; при переходе с L2TP/PSK удаляется ненужный PSK.
Копирование и экспорт профиля не переносят секреты. После импорта введите их заново.

Профиль и новые секреты сохраняются одной командой, и только затем начинается переподключение.
Во время дозвона изменение настроек/профиля/PSK отклоняется с предложением дождаться его завершения.

## Сертификаты

Для PEAP, TTLS и EAP-TLS укажите имена сервера аутентификации из его сертификата
(через `;`) и SHA-1 отпечатки доверенных корневых CA (по одному в строке).
Сертификаты CA должны находиться в `LocalMachine\Root`; проверка сертификата и имени обязательна.
Программа не предлагает принять неизвестный CA в диалоге во время фонового дозвона.

Для EAP-TLS задайте SHA-1 отпечаток клиентского сертификата из `LocalMachine\My`.
Нужны действующий сертификат с назначением Client Authentication, доверенная цепочка,
успешная проверка отзыва и доступ службы LocalSystem к закрытому ключу. Пароль пользователя не нужен.
В машинном режиме IPsec подходящий сертификат выбирает Windows.
Сертификаты/ключи не импортируются автоматически; интерактивные смарт-карты/PIN и MFA не реализованы.

Ссылки на сертификаты и настройки доверия экспортируются; сами сертификаты с закрытыми ключами — нет.
После импорта профиля доступность сертификатов на другом компьютере проверяется перед дозвоном.

## Защита транспорта

Разрешения привязаны к IP-адресам активного VPN-сервера и основному адаптеру:

- SSTP — TCP на настроенный порт (по умолчанию 443).
- L2TP/IPsec — UDP 500/4500/1701, ESP (IP 50).
- IKEv2 — UDP 500/4500, ESP (IP 50).
- PPTP — TCP 1723, GRE (IP 47).
- Cisco AnyConnect — TCP и UDP на порт шлюза (по умолчанию 443).

При переключении старые исключения заменяются. Пользовательские блокировки имеют более высокий
приоритет. Проверяется системный запрет IPsec (`ProhibitIpSec`): при его включении L2TP не запускается.
Настройки NAT-T и доверия Windows автоматически не изменяются. Публичный IPv6 по-прежнему блокируется.

## Cisco AnyConnect

Подключение к Cisco ASA без Cisco-клиента: libopenconnect в процессе-помощнике `SplitVpn.OpenConnect`,
адаптер Wintun. Маршруты, DNS и защита остаются за службой. Ограничения — раздел «Cisco AnyConnect»
в [LIMITATIONS.md](LIMITATIONS.md), устройство — [ANYCONNECT-PLAN.md](ANYCONNECT-PLAN.md).

### Профиль

«Подключения» → новое подключение → протокол «Cisco AnyConnect (вход через SSO)». В мастере первого
запуска AnyConnect не предлагается: мастер создаёт опорное подключение.

- **Сервер** — `host`, `host:port` или `host/group`, например `vpn.example.org` или `vpn.example.org/staff`.
  Порт по умолчанию 443.
- **Роль** — только «Дополнительное» или «Выключено»: опорным AnyConnect не бывает. Способа входа
  в редакторе нет — его выбирает шлюз.
- **Имя пользователя** — необязательно, подставляется в форму шлюза.
- **Группа подключения** — необязательно. Пусто — группа шлюза по умолчанию; группу можно указать и в адресе.
- **Отпечаток клиентского сертификата** — необязательно, SHA-1 из 40 знаков. Сертификат с закрытым ключом —
  в хранилище локального компьютера (`LocalMachine\My`, «Личное»): импортируйте PFX туда.
  Сертификат сервера проверяется по системному хранилищу доверенных корневых CA.
- **DTLS (UDP 443)** — включён по умолчанию. Выключите, если UDP блокируется: трафик пойдёт по TLS (TCP).
- **Применять прокси шлюза (PAC)** — выключено по умолчанию. PAC уводит трафик браузеров на корпоративный
  прокси мимо правил маршрутизации.
- **Идентификатор клиента (User-Agent)** — по умолчанию `AnyConnect Windows 4.10.06090`. Меняйте, если шлюз
  пускает только определённые версии клиента; до 128 печатных символов.

Пробного подключения («Проверить») у AnyConnect нет — используйте «Подключить».

### Вход

- Помощник запускается только по действию пользователя: «Подключить» или «Войти».
- Если шлюз использует SAML SSO, открывается окно встроенного браузера (WebView2). Службе передаются адрес
  страницы и cookie только хоста шлюза. Данные браузера — `%LOCALAPPDATA%\SplitVpn\WebView2`:
  если организация помнит вход, окно закрывается само через несколько секунд.
- Если шлюз просит форму (группа, логин, пароль, одноразовый код), открывается форма шлюза. Пароль не сохраняется.
- Окно открывается само при подключении один раз. Закрытое окно повторно не открывается до кнопки «Войти».
- **Главная:** пока туннель ждёт входа, показана карточка «Требуется вход в «…»» с кнопкой «Войти»
  и причиной последней ошибки. У поднятого туннеля в строке — транспорт (DTLS или TLS) и число сетей шлюза.
- Сеанс не переживает перезапуск службы, помощника и обновление: нужен новый вход.
  Обрыв сети внутри сеанса переподключается без входа.
- Нет WebView2 Runtime — понятная ошибка в окне входа. HostScan/CSD шлюза не поддерживается.

### Сети шлюза и DNS

- **Доска «Маршрутизация»:** для каждого включённого AnyConnect есть карточка «Сети шлюза «…»» — сети Split
  Include, которые назначил шлюз, и его DNS. До входа подпись «Шлюз назначит сети при входе».
- Карточка неудаляемая, по умолчанию стоит в колонке своего подключения. Её можно перенести в «Напрямую»,
  другое подключение или «Блокировать», но не в группу.
- В колонку AnyConnect нельзя перенести «Остальной интернет» и «Россию (RU-базу)»: сеанс поднимается только
  после входа. AnyConnect не входит в группы подключений.
- Сети шлюза действуют только при установленном сеансе. LAN, служебные адреса и DNS других туннелей
  приоритетнее сетей шлюза.
- Суффиксы split DNS шлюза (без однословных вроде `local`) и хост PAC разрешаются через DNS шлюза.
  Эти правила выбирают только DNS-сервер, адреса не закрепляются. Явное доменное правило пользователя важнее.
  Адрес самого шлюза идёт напрямую, мимо туннеля.

### PAC-прокси

При включённом «Применять прокси шлюза» интерфейс ставит адрес PAC из сеанса в настройки прокси
пользователя (WinINet), пока туннель поднят. Прежние настройки сохраняются в
`%LOCALAPPDATA%\SplitVpn\proxy-backup.json` и возвращаются при отключении, выходе интерфейса или
следующем запуске после сбоя. Если пользователь сам изменил прокси, программа его не трогает.
Прокси ставит только запущенный интерфейс; Firefox и программы на WinHTTP его не получают.

### Диагностика и командная строка

- «Диагностика» — сеансы шлюза: адрес, DTLS или TLS, MTU, число сетей, DNS, суффиксы, PAC, срок сеанса.
  Cookie и токены не выводятся.
- `splitvpn-cli tunnels` — состояние туннелей. Для AnyConnect: строка входа («требуется», «открыто окно
  браузера», «шлюз ждёт форму») и строка шлюза (число сетей, DNS, MTU, DTLS/TLS, срок сеанса).
- `splitvpn-cli sign-in --profile <id>` — начать вход. Окно входа откроет запущенный интерфейс;
  id подключения показывает `tunnels` в подсказке к входу.

## Обновление и откат

Настройки имеют схему 2, IPC — контракт 2. Приложение, службу и CLI нужно обновлять вместе;
несовместимая версия получает явную ошибку. Старые настройки схемы 1 читаются как SSTP + MS-CHAPv2.
При первой записи новой схемы оригинал схемы 1 сохраняется в `settings.json.v1.bak`;
эта копия не перезаписывается последующими сохранениями.

Для возврата на 0.1.x сначала восстановите обычный интернет, остановите службу,
сохраните текущие файлы настроек/секретов и верните настройки схемы 1 из этой копии.
Затем устанавливайте старую версию. Новые профили на старой версии не поддерживаются.
Обновление/откат установленной службы в этой ветке не выполнялись.

## Проверки и ограничения приёмки

Локальные результаты и незавершённые сетевые проверки перечислены в
[отчёте](VPN-PROTOCOLS-REPORT.md). Принятие записи API Windows не означает,
что её проверили с реальным сервером. Для новых транспортов пока не подтверждены
реальный выход в интернет, защита при обрыве, NAT-T и сертификатный дозвон от LocalSystem.
