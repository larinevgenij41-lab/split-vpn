# Ограничения

- **Протоколы 0.2.0:** SSTP, L2TP/IPsec, IKEv2, PPTP; WireGuard/OpenVPN отсутствуют. Матрица способов входа и требования сертификатов — [VPN-PROTOCOLS.md](VPN-PROTOCOLS.md). Реальная сетевая приёмка новых протоколов ещё не выполнена — [отчёт](VPN-PROTOCOLS-REPORT.md). Cisco AnyConnect (с 0.3.0) — раздел ниже.

- **IPv6.** Сервер SSTP выдаёт только IPv4, поэтому публичный IPv6 блокируется целиком, пока включена защита. Локальные IPv6 (fe80::/10, fc00::/7), DHCPv6 и обнаружение соседей работают. Без защиты IPv6 не трогается.
- **DNS-over-HTTPS в браузерах.** Браузер с включённым DoH разрешает имена сам, минуя DNS-посредник: запросы идут через VPN, если адрес DoH-сервера не российский. Разделение трафика при этом сохраняется — решение принимается по IP-адресу назначения, а не по имени.
- **Приложения с жёстко заданным DNS** (не системным) при режиме «Разрешить всё напрямую» блокируются DNS-стражем — системный DNS через посредник работает.
- **Маршрутизация по приложениям не поддерживается.** Направить трафик конкретной программы в отдельный туннель в Windows можно только подписанным callout-драйвером WFP: на уровне пользовательских фильтров идентификатор приложения (`ALE_APP_ID`) позволяет разрешить или заблокировать соединение, но не выбрать для него интерфейс. Драйвера в поставке нет, поэтому правила задаются по адресам и доменам.
- **Балансировка — по адресу назначения, а не по соединениям.** Группа делит адресное пространство между туннелями блоками /8: таблица маршрутов Windows умеет только префиксы. Одна закачка целиком остаётся в одном туннеле; суммарная нагрузка расходится по разным. Скорость одного потока группа не увеличивает.
- **Правила по доменам работают через DNS.** Адреса, полученные по правилу, закрепляются за целью на время TTL ответа (не меньше минуты, не больше часа). Браузер с включённым DoH и программа с жёстко заданным DNS правило обойдут: они разрешают имя сами. Если у домена общий IP-адрес с другим доменом (CDN), правило действует на весь этот адрес.
- **Правило по домену не работает в обход своего назначения.** Пока туннель (или все участники группы) не поднят, имя под таким правилом не разрешается — программа получает ошибку DNS, а уже известные адреса этого правила блокируются. Так сделано намеренно: иначе имя ушло бы к DNS провайдера, а трафик — напрямую или в другой VPN. Ответ DNS отдаётся только после того, как маршрут и фильтр применены; если применить их не удалось, программа получает ошибку, а не адрес без защиты. Смена цели правила отзывает прежние закрепления сразу, не дожидаясь конца TTL.
- **Кеш DNS посредника привязан к пути разрешения** (сервер и интерфейс): ответы корпоративного и публичного DNS не смешиваются, а при смене настроек кеш сбрасывается. Когда путь недоступен, посредник отдаёт просроченный ответ, но не старше суток.
- **Другие VPN-программы.** Активное чужое VPN-соединение, чужие маршруты на нашем туннеле и жёсткие разрешения WFP с весом не ниже нашего показываются как конфликты на главной; их поведение программа не изменяет. Radmin VPN и подобные (сеть 26.0.0.0/8 на своём адаптере) работают только при включённом «Локальном доступе».
- **Hyper-V и WSL (NAT).** Трафик виртуальных машин через NAT проходит защиту как трафик хоста; отдельного управления нет.
- **Раздача VPN другим устройствам** (ICS, точка доступа) не поддерживается.
- **Проверка отзыва сертификата SSTP** зависит от системной настройки (см. `CA-TRUST.md`); программа её не меняет.
- **Загрузка RU-базы** возможна при выключенной защите (напрямую) или при подключённом VPN (через туннель). В режиме «защита без VPN» фоновая проверка ждёт подключения.
- **Пороги аномалий базы** (10 % по покрытию, 20 % по числу сетей) не калибруются по истории — история публикаций источника недоступна. Ручной импорт файла эти пороги не проверяет, но и загруженная, и импортированная база отклоняется, если в ней есть сети крупнее /8 или она покрывает больше 1/16 адресного пространства IPv4.
- **Команды службе от администратора без повышения.** Служба принимает изменяющие команды (подключение, настройки, маршруты, режим при обрыве) от администратора интерактивного сеанса и с фильтрованным UAC-токеном: окно приложения работает без запроса UAC. Следствие: любая программа, запущенная под той же учётной записью администратора без повышения, может через канал управления сменить сервер, маршруты или отключить защиту. Граница безопасности здесь — учётная запись, а не UAC; работайте повседневно под обычной учётной записью, если это важно. Секреты по каналу не возвращаются, а сохранённый пароль после смены сервера, протокола или учётной записи удаляется.
- **Установщик не подписан Authenticode.** Windows показывает «Неизвестный издатель», а SmartScreen и Smart App Control на чистой системе могут его остановить. Подлинность обновления обеспечивается иначе: манифест выпуска подписан ключом проекта (ECDSA P-256), открытый ключ зашит в программу, а SHA-256 установщика берётся из подписанного манифеста. Это защищает от подмены пакета в канале, но не снимает предупреждения Windows — см. [UPDATE.md](UPDATE.md).
- **Обновление программы прерывает разрешение имён.** Установка перезапускает службу: фильтры, маршруты и соединение RAS сохраняются, но DNS-посредник останавливается на несколько десятков секунд, а сеанс Cisco AnyConnect закрывается и требует нового входа. Поэтому установка запускается только по команде пользователя, никогда сама.
- **Проверка обновлений** возможна при выключенной защите (напрямую) или при подключённом VPN (через туннель) — то же правило, что у списков адресов.
- **Только Windows 11 x64**, .NET 10 включён в поставку.

## Cisco AnyConnect

Относится к Windows-версии 0.3.0 и новее. Подключение идёт через libopenconnect в процессе-помощнике `SplitVpn.OpenConnect`, роль — только «Дополнительное». Настройка — [VPN-PROTOCOLS.md](VPN-PROTOCOLS.md), решения — [ANYCONNECT-PLAN.md](ANYCONNECT-PLAN.md).

- **Cisco Secure Client (AnyConnect) одновременно не поддерживается.** Его агент `vpnagent` сам управляет маршрутами, DNS и фильтрами и конфликтует со службой. Перед подключением через «Раздельный VPN» отключитесь в Cisco-клиенте; лучше остановить службу агента.
- **Сеанс не переживает перезапуск.** Перезапуск помощника или службы, обновление программы и падение помощника требуют нового входа: сеанс шлюза не переносится в новый процесс. Если организация (ADFS) помнит вход в профиле встроенного браузера, окно закрывается само через несколько секунд без ввода. Обрыв сети внутри живого сеанса переподключается без входа.
- **Вход требует запущенного интерфейса.** Окно SSO и форму шлюза показывает приложение `SplitVpn.exe`. Без него туннель ждёт входа, остальные подключения работают.
- **Внешний браузер для SSO не используется** — только встроенный (WebView2): вход во внешнем браузере ASA поддерживает с 9.17.1. Без WebView2 Runtime вход через SSO невозможен.
- **Пароль в v1 не сохраняется.** Пароль и одноразовые коды вводятся в форме шлюза при каждом входе; имя пользователя подставляется из профиля.
- **Клиентский сертификат — только из хранилища LocalMachine** («Личное» локального компьютера). Сертификаты пользователя (CurrentUser) не поддерживаются: импортируйте PFX в хранилище компьютера.
- **HostScan/CSD не поддерживается.** Шлюз, требующий проверку устройства, вход не пропустит.
- **PAC-прокси ставит и снимает только запущенный интерфейс.** Пока приложение не запущено, прокси не ставится при подключении и не снимается при отключении — до его запуска. Прокси задаётся через WinINet: Firefox и программы на WinHTTP его не получают. По умолчанию выключен: PAC уводит трафик браузеров на корпоративный прокси мимо правил маршрутизации.
- **Аварийное падение службы.** При штатной остановке служба сначала блокирует сети шлюза, затем закрывает сеанс. При аварийном падении помощник завершается вместе со службой, а трафик к сетям шлюза до её рестарта не защищён и идёт по обычным маршрутам.
- **«Tunnel all DNS» сознательно игнорируется.** Через DNS шлюза разрешаются только суффиксы split DNS (однословные вроде `local` пропускаются) и хост PAC; остальные имена — по общим правилам. Эти правила выбирают только DNS-сервер и адреса за туннелем не закрепляют.
- **Split Exclude игнорируется.** В туннель идут сети Split Include; исключения шлюза не применяются, дальше решает доска маршрутизации. Если шлюз не прислал Split Include, сетей шлюза нет — «Остальной интернет» в AnyConnect не направляется.
- **Сети шлюза действуют только при установленном сеансе.** До входа частные адреса (10.0.0.0/8 и т. п.) обрабатываются как локальные (или по ручному правилу, если оно есть) и в интернет не уходят; после завершения сеанса сети шлюза недоступны до нового входа. Пробного подключения («Проверить») у AnyConnect нет.
