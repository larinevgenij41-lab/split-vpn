# Ограничения

- **Протоколы:** SSTP, L2TP/IPsec, IKEv2, PPTP, Cisco AnyConnect (только дополнительным подключением) и «VPN поверх SSH» (только TCP); WireGuard/OpenVPN отсутствуют. Матрица способов входа и требования сертификатов — [VPN-PROTOCOLS.md](VPN-PROTOCOLS.md). Реальная сетевая приёмка новых протоколов ещё не выполнена — [отчёт](VPN-PROTOCOLS-REPORT.md). Cisco AnyConnect (с 0.3.0) и "VPN поверх SSH" (с 0.16.0) - разделы ниже.

- **IPv6.** Сервер SSTP выдаёт только IPv4, поэтому публичный IPv6 блокируется целиком, пока включена защита. Локальные IPv6 (fe80::/10, fc00::/7), DHCPv6 и обнаружение соседей работают. Без защиты IPv6 не трогается.
- **DNS-over-HTTPS в браузерах.** Браузер с включённым DoH разрешает имена сам, минуя DNS-посредник: запросы идут через VPN, если адрес DoH-сервера не российский. Разделение трафика при этом сохраняется — решение принимается по IP-адресу назначения, а не по имени.
- **Приложения с жёстко заданным DNS** (не системным) при режиме «Разрешить всё напрямую» блокируются DNS-стражем — системный DNS через посредник работает.
- **Маршрутизация по приложениям не поддерживается.** Направить трафик конкретной программы в отдельный туннель в Windows можно только подписанным callout-драйвером WFP: на уровне пользовательских фильтров идентификатор приложения (`ALE_APP_ID`) позволяет разрешить или заблокировать соединение, но не выбрать для него интерфейс. Драйвера в поставке нет, поэтому правила задаются по адресам и доменам.
- **Балансировка — по адресу назначения, а не по соединениям.** Группа делит адресное пространство между туннелями блоками /8: таблица маршрутов Windows умеет только префиксы. Одна закачка целиком остаётся в одном туннеле; суммарная нагрузка расходится по разным. Скорость одного потока группа не увеличивает.
- **Правила по доменам работают через DNS.** Адреса, полученные по правилу, закрепляются за целью на время TTL ответа (не меньше минуты, не больше часа). Браузер с включённым DoH и программа с жёстко заданным DNS правило обойдут: они разрешают имя сами. Если у домена общий IP-адрес с другим доменом (CDN), правило действует на весь этот адрес.
- **Правило по домену не работает в обход своего назначения.** Пока туннель (или все участники группы) не поднят, имя под таким правилом не разрешается — программа получает ошибку DNS, а уже известные адреса этого правила блокируются. Так сделано намеренно: иначе имя ушло бы к DNS провайдера, а трафик — напрямую или в другой VPN. Ответ DNS отдаётся только после того, как маршрут и фильтр применены; если применить их не удалось, программа получает ошибку, а не адрес без защиты. Смена цели правила отзывает прежние закрепления сразу, не дожидаясь конца TTL.
- **Кеш DNS посредника привязан к пути разрешения** (сервер и интерфейс): ответы корпоративного и публичного DNS не смешиваются, а при смене настроек кеш сбрасывается. Когда путь недоступен, посредник отдаёт просроченный ответ, но не старше суток.
- **Другие VPN-программы.** Активное чужое VPN-соединение, чужие маршруты на нашем туннеле и жёсткие разрешения WFP с весом не ниже нашего показываются как конфликты на главной; их поведение программа не изменяет. Radmin VPN, Hamachi, ZeroTier и Tailscale распознаются по описанию адаптера: пока включён переключатель «Виртуальные сети» (страница «Защита и DNS»), защита пропускает трафик их адаптера к локальным диапазонам и к его сетям и маршрутам из частных диапазонов и диапазонов поставщика (Radmin VPN - 26.0.0.0/8, Hamachi - 25.0.0.0/8) и без «Локального доступа», а основным он не выбирается. Другую публичную сеть такого адаптера (контроллер ZeroTier может назначить любую) защита локальной не считает - на главной предупреждение. Адаптер, отмеченный в списке «Доверенные адаптеры», доверен целиком: локальны все его сети IPv4 и IPv6 и его собственные маршруты не короче /8 (подсети за маршрутизатором Tailscale, управляемые маршруты ZeroTier); отмечайте так только свою виртуальную сеть - доверие хранится по адаптеру навсегда, и такой адаптер не может стать основным. Публичный интернет через доверенный адаптер (выходной узел Tailscale, маршрут по умолчанию или пара /1 ZeroTier) защита не пропускает - в том числе при обрыве VPN. DNS через доверенный адаптер и блокировки из правил по-прежнему действуют. Служебный трафик самого Radmin VPN (связь с его серверами) идёт через основной адаптер и подчиняется правилам маршрутизации, как любой другой.
- **Hyper-V и WSL (NAT) защитой не покрыты.** Фильтры программы стоят на уровнях соединений самого компьютера (ALE). Трафик виртуальных машин и WSL2, который Windows пересылает через NAT, эти уровни не проходит: он идёт по таблице маршрутов без блокировки при обрыве VPN. Правила разделения на него действуют только через маршруты.
- **Порт 53 на адресе основного адаптера служба занимает эксклюзивно.** DNS-посредник слушает `127.0.0.1:53` (и `[::1]:53`) эксклюзивно, а `0.0.0.0:53` (UDP и TCP) — не эксклюзивно: DNS общего доступа к интернету (ICS, точка доступа на `192.168.137.1`), Hyper-V (Default Switch), Windows Sandbox, WSL и Docker по-прежнему занимают порт 53 на своих адресах. Основному адаптеру ставится DNS «свой адрес, 127.0.0.1» (иначе не проходит проверка интернета Windows), и этот адрес служба перед записью DNS занимает отдельно и эксклюзивно (`SO_EXCLUSIVEADDRUSE`): иначе программа без прав администратора могла бы занять `<адрес адаптера>:53` и получать DNS-запросы всей системы первой. Если порт 53 на адресе основного адаптера уже держит другая программа, адаптеру ставится только `127.0.0.1`, в журнале службы — предупреждение с адресом, и проверка интернета Windows на адаптере может не пройти; захват повторяется на каждой сверке (не реже раза в минуту), и при успехе адрес снова ставится первым. Следствие: программа, которой нужен порт 53 именно на адресе основного адаптера, при включённой защите его не получит.
- **Локальной считается только частная сеть адаптера или сеть доверенного адаптера.** Частная (10/8, 172.16/12, 192.168/16), CGNAT (100.64.0.0/10), link-local сеть, а также 192.0.0.0/29 (DS-Lite) и 198.18.0.0/15 (адаптеры TUN Clash, sing-box с fake-IP), в которой стоит адрес любого поднятого адаптера, идёт напрямую поверх правил, включая "Блокировать". Публичная сеть адаптера локальной считается, только если адаптер доверенный (см. «Другие VPN-программы»): чужая точка доступа с публичной сетью (например, 149.154.160.0/20) иначе открыла бы этот кусок интернета мимо VPN. У недоверенного адаптера с публичной сетью (провайдер с публичным адресом в публичной /24) локален только его маршрутизатор - и то слоем ниже правил пользователя и правил для доменов, только через этот адаптер: точка доступа, назвавшая маршрутизатором ценный адрес (например, сервер Telegram), не выведет его из VPN, если правило `149.154.160.0/20 → туннель` или правило для домена ведёт его в туннель. Транспорт VPN (маршрут к серверу через маршрутизатор), DNS службы и DHCP работают как прежде, а остальная сеть идёт по правилам маршрутизации. Если она назначена туннелю, Windows всё равно отправляет её через адаптер (маршрут сети точнее маршрутов туннеля), и защита такие соединения блокирует: соседи по сети провайдера недоступны. На главной - предупреждение с сетью (о зарезервированных диапазонах - нет). Для основного адаптера оно предлагает правило «сеть → Напрямую» - только если это сеть вашего провайдера, офиса или учебного заведения: в общественной сети (кафе, гостиница) такое правило вывело бы сеть точки доступа из VPN. Отметить адаптер доверенным предлагается только виртуальной сети.
- **Раздача VPN другим устройствам** (ICS, точка доступа) не поддерживается.
- **Проверка туннеля не ловит сервер без выхода в интернет.** Она соединяется с контрольными целями через туннель (по умолчанию для новых установок 1.1.1.1:443 и 1.1.1.1:80; сохранённые настройки не меняются). Туннель рабочий, если хоть одна цель соединилась или ответила сбросом: сервер, который отклоняет отдельные адреса (запрет DoH), иначе рвался бы по кругу. Сброс одной цели при молчании другой - так выглядит сервер без выхода в интернет - пишется предупреждением в журнал службы, но туннель не разрывается: переподключение к тому же серверу этого не исправит.
- **Проверка отзыва сертификата SSTP** зависит от системной настройки (см. `CA-TRUST.md`); программа её не меняет.
- **Адреса проверки отзыва за kill switch** открываются напрямую только на время подъёма подключения (не при поднятом туннеле и не на паузе), только TCP на порт из ссылки (обычно 80) и только через основной адаптер; отдельный маршрут через основной адаптер получает только адрес, который по правилам принадлежит лежащему дополнительному туннелю. Если адрес отзыва совпал с адресом, который правило домена закрепило за туннелем, побеждает правило домена: пока этот туннель лежит, проверка отзыва к такому адресу не пройдёт. Имена берутся только точные и только из сертификата, цепочка которого строится до доверенного корня и выдана на имя сервера. Если сервер не присылает промежуточный сертификат, открывается лишь адрес издателя (AIA) листа — и только при совпадении имени; такой сертификат может предъявить и посторонний с сертификатом на нужное имя от неизвестного УЦ, тогда напрямую откроется одно выбранное им имя. Для сервера, заданного IP-адресом, имя не сверяется: достаточно любой публично доверенной цепочки.
- **Проверка интернета Windows идёт напрямую.** Имя www.msftconnecttest.com разрешает DNS сети, к которой подключён компьютер, а к полученному адресу открыт TCP на порт 80 через основной адаптер - и при обрыве, и в режиме защиты без VPN. Открываются только публичные адреса и не больше четырёх сразу. Если новый DNS-ответ не помещается в лимит или содержит непубличный адрес, он получает отказ целиком; ранее выданные адреса на том же сетевом пути сохраняются до истечения TTL. При смене основного адаптера или его DNS старые служебные закрепления снимаются, запоздалые ответы отвергаются. Предварительные закрепления обновляются за пять минут до окончания часа, при временном сбое DNS служба повторяет попытку. В чужой сети с подменённым DNS это значит, что её владелец может выбрать до четырёх адресов, к которым незашифрованный HTTP (порт 80) любой программы пройдёт напрямую, пока VPN не поднят. Чтобы закрыть это полностью, добавьте правило для домена msftconnecttest.com "через VPN" или "блокировать": правило пользователя отменяет служебное, но тогда Windows до подъёма VPN считает сеть "без интернета" и может сбросить адаптер Wi-Fi.
- **Канал управления** получает случайное имя при каждом запуске службы. В короткий момент, когда у службы нет ни одного экземпляра канала, посторонний процесс может занять это имя; приложение такой канал отвергает (проверяет процесс сервера), но до перезапуска службы управлять ею не сможет.
- **Загрузка RU-базы** возможна при выключенной защите (напрямую) или при подключённом VPN (через туннель). В режиме «защита без VPN» фоновая проверка ждёт подключения.
- **Пороги аномалий базы** (10 % по покрытию, 20 % по числу сетей) не калибруются по истории — история публикаций источника недоступна. Ручной импорт файла эти пороги не проверяет, но и загруженная, и импортированная база отклоняется, если в ней есть сети крупнее /8 или она покрывает больше 1/16 адресного пространства IPv4. Файл для ручного импорта - не больше 2 МБ (предел канала управления); RU-база в текстовом виде занимает несколько сотен килобайт.
- **Команды службе от администратора без повышения.** Служба принимает изменяющие команды (подключение, настройки, маршруты, режим при обрыве) от администратора интерактивного сеанса и с фильтрованным UAC-токеном: окно приложения работает без запроса UAC. Следствие: любая программа, запущенная под той же учётной записью администратора без повышения, может через канал управления без запроса UAC сменить сервер, маршруты или вышестоящий DNS, добавить подключение, пометить адаптер доверенным (его трафик защита пропускает мимо VPN) или отключить защиту. Группа Administrators в фильтрованном токене (только запрет, deny-only) для канала равна полной — это сделано намеренно, чтобы окно приложения работало без UAC. Граница безопасности здесь — учётная запись, а не UAC; работайте повседневно под обычной учётной записью, если это важно. Секреты по каналу не возвращаются, а сохранённый пароль после смены сервера, протокола или учётной записи удаляется.
- **Установщик не подписан Authenticode.** Windows показывает «Неизвестный издатель», а SmartScreen и Smart App Control на чистой системе могут его остановить. Подлинность обновления обеспечивается иначе: манифест выпуска подписан ключом проекта (ECDSA P-256), открытый ключ зашит в программу, а SHA-256 установщика берётся из подписанного манифеста. Это защищает от подмены пакета в канале, но не снимает предупреждения Windows — см. [UPDATE.md](UPDATE.md).
- **Обновление программы прерывает разрешение имён.** Установка перезапускает службу: фильтры, маршруты и соединение RAS сохраняются, но DNS-посредник останавливается на несколько десятков секунд, а сеанс Cisco AnyConnect закрывается и требует нового входа. Поэтому установка запускается только по команде пользователя, никогда сама.
- **Проверка обновлений** возможна при выключенной защите (напрямую) или при подключённом VPN (через туннель) — то же правило, что у списков адресов.
- **Откат с 0.9.6 на 0.9.5 теряет сохранённые пароли, если не вернуть копию.** С 0.9.6 пароли защищаются DPAPI учётной записи службы и хранятся с меткой `user:`, которую 0.9.5 не понимает: она считает файл паролей повреждённым и начинает его заново. Перед первым переносом 0.9.6 оставляет рядом копию в прежнем виде — `secrets.bin.v095` (и `secrets.bin.ipsec.v095` для ключей IPsec, если они были). Удаление программы в конце стирает каталог данных (если сеть вернулась не полностью — только пароли, ключи и VPN-записи программы, остальное остаётся для восстановления; см. [RECOVERY.md](RECOVERY.md), раздел 3), а установщик не ставит старую версию поверх новой, поэтому откат идёт так (PowerShell от администратора):
  ```powershell
  $d = "$env:ProgramData\SplitVpn"
  # 1. До удаления 0.9.6: копия каталога данных с его правами (только SYSTEM и Administrators).
  Stop-Service SplitVpn
  robocopy $d "$d.rollback" /E /COPY:DATS /DCOPY:DAT
  # 2. Удалить 0.9.6, установить 0.9.5. Затем вернуть данные, подставив копии паролей в прежнем виде:
  Stop-Service SplitVpn
  robocopy "$d.rollback" $d /E /COPY:DATS /DCOPY:DAT
  Copy-Item "$d\secrets.bin.v095" "$d\secrets.bin" -Force
  if (Test-Path "$d\secrets.bin.ipsec.v095") { Copy-Item "$d\secrets.bin.ipsec.v095" "$d\secrets.bin.ipsec" -Force }
  Start-Service SplitVpn
  Remove-Item "$d.rollback" -Recurse -Force
  ```
  Пароли, сохранённые или изменённые уже в 0.9.6, после отката придётся ввести заново.
- **Удаление не чистит профиль пользователя.** Установщик работает от имени системы и удаляет только общие данные (`%ProgramData%\SplitVpn`, ключ `HKLM\Software\SplitVpn`). У каждого пользователя, запускавшего интерфейс, остаются запись автозапуска `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\SplitVpn` (если автозапуск был включён; при входе в Windows она указывает на удалённый файл и ничего не запускает) и каталог `%LOCALAPPDATA%\SplitVpn`: настройки интерфейса `ui.json`, журналы `ui-errors.log` и `ui-verbose.log`, копия прежнего прокси `proxy-backup.json` и профили встроенного браузера `WebView2`, `WebView2Profiles` с cookie входа SSO организации. Убрать вручную — под каждой такой учётной записью, после удаления программы (PowerShell, права администратора не нужны):
  ```powershell
  Remove-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name SplitVpn -ErrorAction SilentlyContinue
  Remove-Item "$env:LOCALAPPDATA\SplitVpn" -Recurse -Force
  ```
  Если удаление прошло при поднятом подключении AnyConnect с PAC-прокси и интерфейс не успел его снять, сначала проверьте прокси в «Параметры» → «Сеть и Интернет» → «Прокси-сервер»: после удаления `proxy-backup.json` прежнее значение программа уже не вернёт.
- **Подробный журнал и архив для разбора.** Включает и выключает режим только администратор (как любую команду службы); пользователь без прав видит режим и пишет свой журнал интерфейса, но архив из его сеанса собирается без части службы. Отладочный журнал Cisco AnyConnect начинается со следующего подключения: живой сеанс ради него не перезапускается. Архив не маскирует адреса, имена и учётные записи — передавайте его только тому, кто разбирает проблему. Журналы интерфейса других пользователей попадают в архив, только если их интерфейс уже запускался.
- **Последнее переключение настроек интерфейса может не сохраниться при выходе из Windows и аварийном выходе.** Тема, уведомления и другие настройки интерфейса записываются в фоне. Выход из меню трея и установка обновления ждут записи до 3 секунд, выход из Windows — только уже идущую запись и до 2 секунд (повторное переключение во время неё не записывается), а аварийный выход интерфейса при лавине ошибок не ждёт. Файл `ui.json` при этом не портится: запись атомарная, остаётся прежнее значение.
- **Только Windows 11 x64**, .NET 10 включён в поставку.

## Cisco AnyConnect

Относится к Windows-версии 0.3.0 и новее. Подключение идёт через libopenconnect в процессе-помощнике `SplitVpn.OpenConnect`, роль — только «Дополнительное». Настройка — [VPN-PROTOCOLS.md](VPN-PROTOCOLS.md), решения — [ANYCONNECT-PLAN.md](ANYCONNECT-PLAN.md).

- **Cisco Secure Client (AnyConnect) одновременно не поддерживается.** Его агент `vpnagent` сам управляет маршрутами, DNS и фильтрами и конфликтует со службой. Перед подключением через «Раздельный VPN» отключитесь в Cisco-клиенте; лучше остановить службу агента.
- **Сеанс не переживает перезапуск.** Перезапуск помощника или службы, обновление программы и падение помощника требуют нового входа: сеанс шлюза не переносится в новый процесс. Если организация (ADFS) помнит вход в профиле встроенного браузера, окно закрывается само через несколько секунд без ввода. Обрыв сети внутри живого сеанса переподключается без входа.
- **Вход требует запущенного интерфейса.** Окно SSO и форму шлюза показывает приложение `SplitVpn.exe`. Без него туннель ждёт входа, остальные подключения работают.
- **Внешний браузер для SSO не используется** — только встроенный (WebView2): вход во внешнем браузере ASA поддерживает с 9.17.1. Без WebView2 Runtime вход через SSO невозможен. Шлюз, настроенный только на вход во внешнем браузере, не пропустит: помощник, не получивший сеанс за 90 секунд без действий пользователя, останавливается, и туннель снова просит вход.
- **У каждого подключения AnyConnect свой профиль встроенного браузера.** Прежний общий профиль переносится один раз, в профиль первого подключения, открывшего вход после обновления до 0.15.3; если перенос не удался (профиль был занят), общий профиль удаляется. Для остальных подключений вход в SSO организации понадобится один раз заново. Удаление подключения удаляет его профиль браузера (у текущего пользователя Windows).
- **Обрыв сети внутри сеанса** переподключается без входа в течение 5 минут; после этого сеанс завершается и нужен новый вход.
- **Пароль в v1 не сохраняется.** Пароль и одноразовые коды вводятся в форме шлюза при каждом входе; имя пользователя подставляется из профиля.
- **Клиентский сертификат — только из хранилища LocalMachine** («Личное» локального компьютера). Сертификаты пользователя (CurrentUser) не поддерживаются: импортируйте PFX в хранилище компьютера. Ключ должен лежать в классическом хранилище ключей (CryptoAPI): ключи компьютера в поставщиках CNG (программный KSP, TPM) библиотека GnuTLS открыть не может, и программа сообщает об этом при подключении.
- **HostScan/CSD не поддерживается.** Шлюз, требующий проверку устройства, вход не пропустит.
- **PAC-прокси ставит и снимает только запущенный интерфейс.** Пока приложение не запущено, прокси не ставится при подключении и не снимается при отключении — до его запуска. Прокси задаётся через WinINet: Firefox и программы на WinHTTP его не получают. По умолчанию выключен: PAC уводит трафик браузеров на корпоративный прокси мимо правил маршрутизации.
- **Аварийное падение службы.** При штатной остановке служба снимает сети шлюза и закрывает сеанс, дождавшись, пока помощники попрощаются со шлюзом. При аварийном падении помощник завершается вместе со службой; до рестарта службы трафик к сетям шлюза идёт по обычным маршрутам.
- **«Tunnel all DNS» сознательно игнорируется.** Через DNS шлюза разрешаются только суффиксы split DNS (однословные вроде `local` пропускаются) и хост PAC; остальные имена — по общим правилам. Эти правила выбирают только DNS-сервер и адреса за туннелем не закрепляют.
- **Split Exclude игнорируется.** В туннель идут сети Split Include; исключения шлюза не применяются, дальше решает доска маршрутизации. Если шлюз не прислал Split Include, сетей шлюза нет — «Остальной интернет» в AnyConnect не направляется.
- **Сети шлюза ограничены.** Сеть шире /8 отбрасывается поштучно. Весь набор сетей шлюза, который после свёртки покрывает больше 1/16 адресного пространства IPv4 или содержит больше 16 384 маршрутов (после свёртки смежных сетей), отбрасывается целиком: сетей шлюза у подключения нет, а в журнале службы — предупреждение с причиной. Обычный корпоративный Split Include, даже из тысяч несмежных /24, в эти пределы укладывается.
- **Сети шлюза уступают ручным правилам.** По умолчанию адрес под ручным правилом доски идёт по нему, даже если шлюз прислал охватывающую сеть (например, 10.0.0.0/8). Поэтому широкое ручное правило (скажем, `10.0.0.0/8 → Напрямую`) отберёт у шлюза все его сети в этом диапазоне. Прежний порядок включается снятием галочки «Ручные правила важнее сетей шлюза» на карточке. С этой галочкой адрес DNS-сервера шлюза уступает только запрету («Блокировать») и правилу ровно на этот адрес (/32) с другой целью: такой адрес убирается из DNS туннеля (предупреждение на главной). Широкое правило (`10.0.0.0/8 → Напрямую`) DNS шлюза не отбирает - он остаётся в туннеле. Если у подключения не осталось ни одного DNS шлюза, имена split DNS и правил для доменов в это подключение не разрешаются (ошибка DNS), а не уходят к публичным резолверам: иначе внутренние имена компании утекли бы к 1.1.1.1 и 8.8.8.8.
- **Туннель AnyConnect - только IPv4.** Помощник отключает IPv6 в сеансе; защита пропускает через туннель AnyConnect только IPv4. Если отключить IPv6 не удалось, на главной - предупреждение, а IPv6 через туннель блокируется.
- **Сети шлюза действуют только при установленном сеансе.** До входа и после конца сеанса (обрыв, ограничение времени шлюза, перезапуск службы, обновление программы) сетей шлюза нет: частные адреса (10.0.0.0/8 и т. п.) обрабатываются как локальные (или по ручному правилу, если оно есть), публичные идут по обычным правилам, а имена split DNS шлюза разрешает общий DNS. Поэтому вне сеанса корпоративные адреса недоступны, а корпоративное имя может разрешиться общим DNS в публичный адрес. Пробного подключения («Проверить») у AnyConnect нет.
## Доменные закрепления DNS

- Запоздалый ответ прежней конфигурации отклоняется. CNAME-связи подтверждаются вместе с
  ответом; отвергнутый ответ не создаёт новую связь. Общая CNAME-цель несовместимых правил
  получает SERVFAIL для второго ответа, без переназначения ранее выданного пути.
- Таблица CNAME ограничена 10 000 канонических имён. При заполнении новые связи не выдаются
  клиенту; истечение TTL освобождает место. Совместимые владельцы сохраняют свои сроки.
- Запрос ANY под доменным правилом отклоняется. Для получения адреса используйте обычный
  запрос A; CNAME-наследование работает и для отдельного запроса CNAME.
- Если два доменных правила направляют один IP в разные цели, сохраняется действующее
  закрепление до окончания TTL, а конфликтующий DNS-ответ получает SERVFAIL. Новые адреса
  из такого ответа частично не применяются.
- Закрепление действует на адрес, а не на домен: пока оно живо, по нему идут соединения всех программ и
  всех доменов с тем же адресом (общие адреса CDN). Домен под правилом «напрямую» при «остальном» в туннеле
  выводит из VPN и чужие сайты на том же адресе CDN.
- Закрепление живёт дольше TTL ответа, чтобы не рвать открытые соединения: 5 минут после истечения TTL -
  всегда, дальше - пока в системной таблице есть установленное соединение TCP к адресу (проверка раз в
  минуту, к адресу от любой программы). Предел продления - сутки после TTL, а для закрепления «напрямую» на
  адресе, который без него шёл бы в туннель или блокировался, - час после TTL: так ограничено время, когда
  чужие домены на этом адресе идут мимо VPN. Новые соединения программа открывает по новому запросу DNS:
  клиенту TTL не продлевается. Продлённое закрепление уступает адрес свежему ответу другого домена с другой
  целью и снимается сразу при смене правила или разрыве его туннеля.
- Закрепления переживают перезапуск службы (обновление, сбой, ручной перезапуск), но не перезагрузку Windows:
  служба сохраняет их в `pins.json` в своём каталоге данных (не чаще раза в 30 секунд при заметных изменениях
  и при остановке) и восстанавливает до первой сверки. После перезагрузки файл удаляется: программы всё равно
  спросят DNS заново, а устаревший адрес увёл бы чужие домены с общим адресом сети доставки. Простой службы
  считается по времени работы Windows, поэтому перевод часов сроки не продлевает. Восстановленные проверяются
  заново: правило исчезло или сменило цель, адрес теперь отклоняется политикой - закрепление снимается; основной
  срок - не дольше часа от запуска, продление решает таблица соединений, как обычно. Если служба упала раньше
  записи, закрепления последних секунд теряются, и программы со своим кешем адресов (браузеры, Java, Telegram) до
  нового запроса DNS идут по адресной политике. «Отключить» и экстренное отключение удаляют файл сразу, удаление программы - всегда, даже
  если сеть восстановлена не полностью. Файл в архив диагностики не входит: по нему видно, какие сайты открывались.
- Потоки UDP, в том числе QUIC (HTTP/3, видео, звонки), в таблице соединений не видны: после истечения TTL они
  держатся только 5 минут. Затем адрес идёт по адресной политике, и такой поток может оборваться или
  переключиться на TCP.
- Из одного ответа DNS закрепляется не больше 16 адресов (лишние записи вырезаются из ответа), на одно
  правило для домена - не больше 2000 адресов. Сверх доли правила новые адреса не закрепляются (лишние
  вырезаются, ответ без единого адреса - SERVFAIL); на главной - предупреждение, другие правила это не задевает.
- При 10 000 динамических IP-закреплений новые IP из DNS временно не принимаются (SERVFAIL).
  Обновление существующих записей работает; истечение TTL освобождает место, а продлённые закрепления
  вытесняются первыми.
- CNAME-связь создаёт только ответ из одних CNAME, живёт 5-30 секунд и передаёт каноническому имени
  только цели «туннель» и «блокировать», но не «напрямую».
- Правило для домена может увести адрес в туннель, но не вывести его из туннеля (порядок - в
  DOMAIN-ROUTING-PLAN.md). Цель «туннель» закрепляет и адреса частных сетей (корпоративные имена в 10.x):
  пока туннель лежит, такой адрес блокируется. Цель «напрямую» на частный адрес не закрепляется: адрес
  остаётся локальным. Не закрепляются (отказ) адрес под запретом пользователя, в сети шлюза AnyConnect с
  другой целью, в документационном диапазоне, а для цели «напрямую» - и адрес под CIDR-правилом в туннель
  с более высоким приоритетом (при равном приоритете правило для домена важнее; частный адрес под таким
  правилом - отказ всегда). При отказе программа получает ошибку DNS (SERVFAIL), а не адрес мимо правила;
  на главной - предупреждение с правилом и причиной, в журнале службы - запись. 198.18.0.0/15 (fake-IP)
  закрепляется с любой целью.
- DNS сети (DHCP) не перекрывает правила пользователя: правило в туннель или «Блокировать» действует для
  программ, а служба по-прежнему разрешает через этот DNS имена серверов VPN (только через основной адаптер).

## VPN поверх SSH

Относится к Windows-версии 0.16.0 и новее. Туннель держит отдельная программа-движок (sing-box, входит в установщик): она переносит трафик из своего сетевого адаптера в одно соединение SSH с сервером. Маршруты, DNS и защита остаются у службы, как для остальных подключений. Настройка - [VPN-PROTOCOLS.md](VPN-PROTOCOLS.md).

- **Только TCP.** SSH не переносит UDP: звонки, игры и QUIC через это подключение не работают. UDP в туннеле блокируется сразу, поэтому браузеры без задержки открывают сайты по TCP. Ping через туннель не проходит.
- **Одно соединение на весь трафик.** Все потоки идут внутри одного TCP-соединения с сервером: при потерях в сети замедляется всё сразу, а не один поток.
- **DNS через туннель идёт по TCP.** Запрос без ответа в кеше - это новое соединение через туннель, первое открытие сайта может занять на 0,3-0,5 с больше.
- **Одно такое подключение одновременно.** Второе можно завести, но включить вместе с первым нельзя. В группы подключений этот тип не входит.
- **Ключ сервера обязателен.** Подключение сверяет сервер с закреплённым ключом при каждом входе; варианта "не проверять" нет. Сменился ключ сервера - подключение останавливается и ждёт, пока вы укажете новый.
- **Ключ устройства - только файл OpenSSH без пароля.** Ключ хранится в службе зашифрованным (DPAPI), как пароли, и в экспорт подключений не входит. Вход по паролю SSH не поддерживается.
- **Отказ входа повторов не вызывает.** Если сервер не принял ключ или предъявил чужой ключ, служба не повторяет попытки: частые попытки сервер может принять за подбор. После исправления нажмите "Подключить".
- **Сеанс не переживает службу.** Перезапуск службы, обновление программы и её аварийное падение завершают движок; туннель поднимается заново сам, вход пользователя не нужен. Пока туннель не поднят, назначенный ему трафик блокируется.
- **Обрыв связи замечается не мгновенно.** Раз в 30 секунд и после смены сети служба проверяет туннель запросом через него; после двух неудач подряд движок перезапускается. До этого трафик туннеля не идёт никуда - напрямую он не уходит.
- **Программа движка ограничена своим сервером.** Защита разрешает sing-box.exe только TCP на адрес и порт сервера подключения через основной адаптер. Другой sing-box на этом компьютере (из другой программы) служба не трогает.
- **Нет пробного подключения.** Кнопка "Проверить профиль" для этого типа не работает: подключение проверяется обычным "Подключить".
