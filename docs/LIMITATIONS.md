# Ограничения

- **Протоколы 0.2.0:** SSTP, L2TP/IPsec, IKEv2, PPTP; WireGuard/OpenVPN отсутствуют. Матрица способов входа и требования сертификатов — [VPN-PROTOCOLS.md](VPN-PROTOCOLS.md). Реальная сетевая приёмка новых протоколов ещё не выполнена — [отчёт](VPN-PROTOCOLS-REPORT.md). Cisco AnyConnect (с 0.3.0) — раздел ниже.

- **IPv6.** Сервер SSTP выдаёт только IPv4, поэтому публичный IPv6 блокируется целиком, пока включена защита. Локальные IPv6 (fe80::/10, fc00::/7), DHCPv6 и обнаружение соседей работают. Без защиты IPv6 не трогается.
- **DNS-over-HTTPS в браузерах.** Браузер с включённым DoH разрешает имена сам, минуя DNS-посредник: запросы идут через VPN, если адрес DoH-сервера не российский. Разделение трафика при этом сохраняется — решение принимается по IP-адресу назначения, а не по имени.
- **Приложения с жёстко заданным DNS** (не системным) при режиме «Разрешить всё напрямую» блокируются DNS-стражем — системный DNS через посредник работает.
- **Маршрутизация по приложениям не поддерживается.** Направить трафик конкретной программы в отдельный туннель в Windows можно только подписанным callout-драйвером WFP: на уровне пользовательских фильтров идентификатор приложения (`ALE_APP_ID`) позволяет разрешить или заблокировать соединение, но не выбрать для него интерфейс. Драйвера в поставке нет, поэтому правила задаются по адресам и доменам.
- **Балансировка — по адресу назначения, а не по соединениям.** Группа делит адресное пространство между туннелями блоками /8: таблица маршрутов Windows умеет только префиксы. Одна закачка целиком остаётся в одном туннеле; суммарная нагрузка расходится по разным. Скорость одного потока группа не увеличивает.
- **Правила по доменам работают через DNS.** Адреса, полученные по правилу, закрепляются за целью на время TTL ответа (не меньше минуты, не больше часа). Браузер с включённым DoH и программа с жёстко заданным DNS правило обойдут: они разрешают имя сами. Если у домена общий IP-адрес с другим доменом (CDN), правило действует на весь этот адрес.
- **Правило по домену не работает в обход своего назначения.** Пока туннель (или все участники группы) не поднят, имя под таким правилом не разрешается — программа получает ошибку DNS, а уже известные адреса этого правила блокируются. Так сделано намеренно: иначе имя ушло бы к DNS провайдера, а трафик — напрямую или в другой VPN. Ответ DNS отдаётся только после того, как маршрут и фильтр применены; если применить их не удалось, программа получает ошибку, а не адрес без защиты. Смена цели правила отзывает прежние закрепления сразу, не дожидаясь конца TTL.
- **Кеш DNS посредника привязан к пути разрешения** (сервер и интерфейс): ответы корпоративного и публичного DNS не смешиваются, а при смене настроек кеш сбрасывается. Когда путь недоступен, посредник отдаёт просроченный ответ, но не старше суток.
- **Другие VPN-программы.** Активное чужое VPN-соединение, чужие маршруты на нашем туннеле и жёсткие разрешения WFP с весом не ниже нашего показываются как конфликты на главной; их поведение программа не изменяет. Radmin VPN, Hamachi, ZeroTier и Tailscale распознаются по описанию адаптера: пока включён переключатель «Виртуальные сети» (страница «Защита и DNS»), защита пропускает трафик их адаптера и без «Локального доступа», а основным он не выбирается. Другой такой адаптер можно отметить там же в списке «Доверенные адаптеры». DNS через доверенный адаптер и блокировки из правил по-прежнему действуют. Служебный трафик самого Radmin VPN (связь с его серверами) идёт через основной адаптер и подчиняется правилам маршрутизации, как любой другой.
- **Hyper-V и WSL (NAT) защитой не покрыты.** Фильтры программы стоят на уровнях соединений самого компьютера (ALE). Трафик виртуальных машин и WSL2, который Windows пересылает через NAT, эти уровни не проходит: он идёт по таблице маршрутов без блокировки при обрыве VPN. Правила разделения на него действуют только через маршруты.
- **Локальная сеть адаптера считается локальной целиком.** Сеть, в которой стоит адрес любого поднятого адаптера, идёт напрямую поверх правил, включая "Блокировать". В публичной сети Wi-Fi с широкой маской (например, /8 из публичных адресов) напрямую пойдёт и эта часть интернета. Ограничить локальные сети только частными диапазонами нельзя: виртуальные сети вроде Radmin VPN (26.0.0.0/8) перестали бы работать.
- **Раздача VPN другим устройствам** (ICS, точка доступа) не поддерживается.
- **Проверка туннеля не ловит сервер без выхода в интернет.** Она соединяется с контрольными целями через туннель (по умолчанию для новых установок 1.1.1.1:443 и 1.1.1.1:80; сохранённые настройки не меняются). Туннель рабочий, если хоть одна цель соединилась или ответила сбросом: сервер, который отклоняет отдельные адреса (запрет DoH), иначе рвался бы по кругу. Сброс одной цели при молчании другой - так выглядит сервер без выхода в интернет - пишется предупреждением в журнал службы, но туннель не разрывается: переподключение к тому же серверу этого не исправит.
- **Проверка отзыва сертификата SSTP** зависит от системной настройки (см. `CA-TRUST.md`); программа её не меняет.
- **Адреса проверки отзыва за kill switch** открываются напрямую только на время подъёма подключения (не при поднятом туннеле и не на паузе), только TCP на порт из ссылки (обычно 80) и только через основной адаптер; отдельный маршрут через основной адаптер получает только адрес, который по правилам принадлежит лежащему дополнительному туннелю. Если адрес отзыва совпал с адресом, который правило домена закрепило за туннелем, побеждает правило домена: пока этот туннель лежит, проверка отзыва к такому адресу не пройдёт. Имена берутся только точные и только из сертификата, цепочка которого строится до доверенного корня и выдана на имя сервера. Если сервер не присылает промежуточный сертификат, открывается лишь адрес издателя (AIA) листа — и только при совпадении имени; такой сертификат может предъявить и посторонний с сертификатом на нужное имя от неизвестного УЦ, тогда напрямую откроется одно выбранное им имя. Для сервера, заданного IP-адресом, имя не сверяется: достаточно любой публично доверенной цепочки.
- **Проверка интернета Windows идёт напрямую.** Имя www.msftconnecttest.com разрешает DNS сети, к которой подключён компьютер, а к полученному адресу открыт TCP на порт 80 через основной адаптер - и при обрыве, и в режиме защиты без VPN. Открываются только публичные адреса и не больше четырёх сразу. Если новый DNS-ответ не помещается в лимит или содержит непубличный адрес, он получает отказ целиком; ранее выданные адреса на том же сетевом пути сохраняются до истечения TTL. При смене основного адаптера или его DNS старые служебные закрепления снимаются, запоздалые ответы отвергаются. Предварительные закрепления обновляются за пять минут до окончания часа, при временном сбое DNS служба повторяет попытку. В чужой сети с подменённым DNS это значит, что её владелец может выбрать до четырёх адресов, к которым незашифрованный HTTP (порт 80) любой программы пройдёт напрямую, пока VPN не поднят. Чтобы закрыть это полностью, добавьте правило для домена msftconnecttest.com "через VPN" или "блокировать": правило пользователя отменяет служебное, но тогда Windows до подъёма VPN считает сеть "без интернета" и может сбросить адаптер Wi-Fi.
- **Канал управления** получает случайное имя при каждом запуске службы. В короткий момент, когда у службы нет ни одного экземпляра канала, посторонний процесс может занять это имя; приложение такой канал отвергает (проверяет процесс сервера), но до перезапуска службы управлять ею не сможет.
- **Загрузка RU-базы** возможна при выключенной защите (напрямую) или при подключённом VPN (через туннель). В режиме «защита без VPN» фоновая проверка ждёт подключения.
- **Пороги аномалий базы** (10 % по покрытию, 20 % по числу сетей) не калибруются по истории — история публикаций источника недоступна. Ручной импорт файла эти пороги не проверяет, но и загруженная, и импортированная база отклоняется, если в ней есть сети крупнее /8 или она покрывает больше 1/16 адресного пространства IPv4. Файл для ручного импорта - не больше 2 МБ (предел канала управления); RU-база в текстовом виде занимает несколько сотен килобайт.
- **Команды службе от администратора без повышения.** Служба принимает изменяющие команды (подключение, настройки, маршруты, режим при обрыве) от администратора интерактивного сеанса и с фильтрованным UAC-токеном: окно приложения работает без запроса UAC. Следствие: любая программа, запущенная под той же учётной записью администратора без повышения, может через канал управления сменить сервер, маршруты или отключить защиту. Граница безопасности здесь — учётная запись, а не UAC; работайте повседневно под обычной учётной записью, если это важно. Секреты по каналу не возвращаются, а сохранённый пароль после смены сервера, протокола или учётной записи удаляется.
- **Установщик не подписан Authenticode.** Windows показывает «Неизвестный издатель», а SmartScreen и Smart App Control на чистой системе могут его остановить. Подлинность обновления обеспечивается иначе: манифест выпуска подписан ключом проекта (ECDSA P-256), открытый ключ зашит в программу, а SHA-256 установщика берётся из подписанного манифеста. Это защищает от подмены пакета в канале, но не снимает предупреждения Windows — см. [UPDATE.md](UPDATE.md).
- **Обновление программы прерывает разрешение имён.** Установка перезапускает службу: фильтры, маршруты и соединение RAS сохраняются, но DNS-посредник останавливается на несколько десятков секунд, а сеанс Cisco AnyConnect закрывается и требует нового входа. Поэтому установка запускается только по команде пользователя, никогда сама.
- **Проверка обновлений** возможна при выключенной защите (напрямую) или при подключённом VPN (через туннель) — то же правило, что у списков адресов.
- **Откат с 0.9.6 на 0.9.5 теряет сохранённые пароли, если не вернуть копию.** С 0.9.6 пароли защищаются DPAPI учётной записи службы и хранятся с меткой `user:`, которую 0.9.5 не понимает: она считает файл паролей повреждённым и начинает его заново. Перед первым переносом 0.9.6 оставляет рядом копию в прежнем виде — `secrets.bin.v095` (и `secrets.bin.ipsec.v095` для ключей IPsec, если они были). Удаление программы стирает весь каталог данных, а установщик не ставит старую версию поверх новой, поэтому откат идёт так (PowerShell от администратора):
  ```powershell
  $d = "$env:ProgramData\SplitVpn"
  # 1. До удаления 0.9.6: копия каталога данных с его правами (только SYSTEM и Administrators).
  Stop-Service SplitVpn
  robocopy $d "$d.rollback" /E /COPY:DATS /DCOPY:DAT
  # 2. Удалить 0.9.6, установить 0.9.5. Затем вернуть данные, подставив копии паролей в прежнем виде:
  Stop-Service SplitVpn
  robocopy "$d.rollback" $d /E /COPY:DATS /DCOPY:DAT
  Copy-Item "$d\secrets.bin.v095" "$d\secrets.bin" -Force
  if (Test-Path "$d\secrets.bin.ipsec.v095") { Copy-Item "$d\secrets.bin.ipsec.v095" "$d\secrets.bin.ipsec" -Force }
  Start-Service SplitVpn
  Remove-Item "$d.rollback" -Recurse -Force
  ```
  Пароли, сохранённые или изменённые уже в 0.9.6, после отката придётся ввести заново.
- **Подробный журнал и архив для разбора.** Включает и выключает режим только администратор (как любую команду службы); пользователь без прав видит режим и пишет свой журнал интерфейса, но архив из его сеанса собирается без части службы. Отладочный журнал Cisco AnyConnect начинается со следующего подключения: живой сеанс ради него не перезапускается. Архив не маскирует адреса, имена и учётные записи — передавайте его только тому, кто разбирает проблему. Журналы интерфейса других пользователей попадают в архив, только если их интерфейс уже запускался.
- **Только Windows 11 x64**, .NET 10 включён в поставку.

## Cisco AnyConnect

Относится к Windows-версии 0.3.0 и новее. Подключение идёт через libopenconnect в процессе-помощнике `SplitVpn.OpenConnect`, роль — только «Дополнительное». Настройка — [VPN-PROTOCOLS.md](VPN-PROTOCOLS.md), решения — [ANYCONNECT-PLAN.md](ANYCONNECT-PLAN.md).

- **Cisco Secure Client (AnyConnect) одновременно не поддерживается.** Его агент `vpnagent` сам управляет маршрутами, DNS и фильтрами и конфликтует со службой. Перед подключением через «Раздельный VPN» отключитесь в Cisco-клиенте; лучше остановить службу агента.
- **Сеанс не переживает перезапуск.** Перезапуск помощника или службы, обновление программы и падение помощника требуют нового входа: сеанс шлюза не переносится в новый процесс. Если организация (ADFS) помнит вход в профиле встроенного браузера, окно закрывается само через несколько секунд без ввода. Обрыв сети внутри живого сеанса переподключается без входа.
- **Вход требует запущенного интерфейса.** Окно SSO и форму шлюза показывает приложение `SplitVpn.exe`. Без него туннель ждёт входа, остальные подключения работают.
- **Внешний браузер для SSO не используется** — только встроенный (WebView2): вход во внешнем браузере ASA поддерживает с 9.17.1. Без WebView2 Runtime вход через SSO невозможен. Шлюз, настроенный только на вход во внешнем браузере, не пропустит: помощник, не получивший сеанс за 90 секунд без действий пользователя, останавливается, и туннель снова просит вход.
- **У каждого подключения AnyConnect свой профиль встроенного браузера.** Прежний общий профиль переносится один раз, в профиль первого подключения, открывшего вход после обновления до 0.15.3; если перенос не удался (профиль был занят), общий профиль удаляется. Для остальных подключений вход в SSO организации понадобится один раз заново. Удаление подключения удаляет его профиль браузера (у текущего пользователя Windows).
- **Обрыв сети внутри сеанса** переподключается без входа в течение 5 минут; после этого сеанс завершается и нужен новый вход.
- **Пароль в v1 не сохраняется.** Пароль и одноразовые коды вводятся в форме шлюза при каждом входе; имя пользователя подставляется из профиля.
- **Клиентский сертификат — только из хранилища LocalMachine** («Личное» локального компьютера). Сертификаты пользователя (CurrentUser) не поддерживаются: импортируйте PFX в хранилище компьютера. Ключ должен лежать в классическом хранилище ключей (CryptoAPI): ключи компьютера в поставщиках CNG (программный KSP, TPM) библиотека GnuTLS открыть не может, и программа сообщает об этом при подключении.
- **HostScan/CSD не поддерживается.** Шлюз, требующий проверку устройства, вход не пропустит.
- **PAC-прокси ставит и снимает только запущенный интерфейс.** Пока приложение не запущено, прокси не ставится при подключении и не снимается при отключении — до его запуска. Прокси задаётся через WinINet: Firefox и программы на WinHTTP его не получают. По умолчанию выключен: PAC уводит трафик браузеров на корпоративный прокси мимо правил маршрутизации.
- **Аварийное падение службы.** При штатной остановке служба снимает сети шлюза и закрывает сеанс, дождавшись, пока помощники попрощаются со шлюзом. При аварийном падении помощник завершается вместе со службой; до рестарта службы трафик к сетям шлюза идёт по обычным маршрутам.
- **«Tunnel all DNS» сознательно игнорируется.** Через DNS шлюза разрешаются только суффиксы split DNS (однословные вроде `local` пропускаются) и хост PAC; остальные имена — по общим правилам. Эти правила выбирают только DNS-сервер и адреса за туннелем не закрепляют.
- **Split Exclude игнорируется.** В туннель идут сети Split Include; исключения шлюза не применяются, дальше решает доска маршрутизации. Если шлюз не прислал Split Include, сетей шлюза нет — «Остальной интернет» в AnyConnect не направляется.
- **Сети шлюза уступают ручным правилам.** По умолчанию адрес под ручным правилом доски идёт по нему, даже если шлюз прислал охватывающую сеть (например, 10.0.0.0/8). Поэтому широкое ручное правило (скажем, `10.0.0.0/8 → Напрямую`) отберёт у шлюза все его сети в этом диапазоне. Прежний порядок включается снятием галочки «Ручные правила важнее сетей шлюза» на карточке.
- **Сети шлюза действуют только при установленном сеансе.** До входа и после конца сеанса (обрыв, ограничение времени шлюза, перезапуск службы, обновление программы) сетей шлюза нет: частные адреса (10.0.0.0/8 и т. п.) обрабатываются как локальные (или по ручному правилу, если оно есть), публичные идут по обычным правилам, а имена split DNS шлюза разрешает общий DNS. Поэтому вне сеанса корпоративные адреса недоступны, а корпоративное имя может разрешиться общим DNS в публичный адрес. Пробного подключения («Проверить») у AnyConnect нет.
## Доменные закрепления DNS

- При смене правила во время запроса запоздалый ответ только с CNAME может пройти без
  наследования правила каноническим именем. Следующий запрос канонического имени в этом
  случае уходит к общему DNS, в том числе после смены исходного правила на блокировку.
  Ошибка подтверждена тестом и в 0.15.11 ещё не исправлена.
- Если два доменных правила направляют один IP в разные цели, сохраняется действующее
  закрепление до окончания TTL, а конфликтующий DNS-ответ получает SERVFAIL. Новые адреса
  из такого ответа частично не применяются.
- При 10 000 динамических IP-закреплений новые IP из DNS временно не принимаются (SERVFAIL).
  Обновление существующих записей работает; истечение TTL освобождает место.
