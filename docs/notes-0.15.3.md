Подключение заметно меньше нагружает Windows: фильтров защиты WFP несколько сотен вместо десятков тысяч, а маршрутов при "остальном интернете через VPN" примерно на треть меньше. Исправлены переподключения по кругу при проверке туннеля и блокировка сети после сброса сети Windows, а также ошибки защиты при обрывах, AnyConnect и DNS. Версии 0.15.0-0.15.2 отдельно не выпускались, их изменения вошли в этот выпуск.

## Меньше нагрузки на Windows

- **Пакетные фильтры защиты.** Диапазоны прямого выхода и назначений туннелей собираются по 512 в один фильтр WFP с условием "любой из". Фильтров становится несколько сотен вместо 50-60 тысяч, установка и сверка защиты при подключении идут быстрее. Фильтры "Туннель недоступен" при обрыве дополнительного туннеля тоже собираются пакетами.
- **Оптимальная свёртка списка обхода.** Из всех вариантов свёртки выбирается тот, что даёт меньше всего маршрутов, а одиночный адрес не расширяется до подсети, если маршрут от этого не экономится. По умолчанию подсети до /18 (было /24): на текущем списке около 5 100 маршрутов вместо 8 500. Российские адреса, которых нет в самом списке, по-прежнему идут напрямую. Свёртка выбирается в "Настройках", блок "Обновление списка обхода блокировок", пункт "Объединять адреса в подсети": от "Не объединять" до подсетей /16.
- **Маршруты с исключениями.** При "остальном интернете через VPN" российские сети ставятся широкими прямыми маршрутами, а немногие зарубежные адреса внутри них возвращаются в туннель более узкими маршрутами. Windows выбирает самый узкий подходящий маршрут, поэтому каждый адрес идёт туда же, куда раньше. На проверочном компьютере системных маршрутов стало около 13 тысяч вместо 20. Локальные сети маршрутами не затрагиваются. Учитывается и маршрут, который Windows сам ставит на последний адрес каждой сети туннеля: российские адреса на границе сетей не уходят в туннель.
- **Обрыв туннеля не перестраивает прямые маршруты.** При обрыве и переподключении снимаются и ставятся только маршруты самого туннеля.
- Проверка конфликтов работает в фоне и не задерживает службу. Маршруты, выданные сервером при подключении, больше не показываются как конфликт.
- При выходе из Windows и выключении служба не пытается ставить тысячи маршрутов на уже исчезнувший туннель.

## Подключения и защита

- **Проверка туннеля.** Отказ в соединении (TCP RST) от контрольной цели, пришедший через туннель, считается признаком рабочего туннеля. Если сервер VPN закрывает клиентам, например, DoH к 1.1.1.1:443, прежняя проверка рвала живой туннель каждые 15 секунд. Контрольных целей можно указать несколько через запятую (для новых установок по умолчанию 1.1.1.1:443 и 1.1.1.1:80). Если одна цель ответила сбросом, а другая молчит (так выглядит сервер без выхода в интернет), в журнал службы пишется предупреждение.
- **Закреплённый адаптер после сброса сети Windows.** Сброс сети выдаёт адаптеру новый идентификатор. Служба запоминает описание закреплённого адаптера и переносит закрепление на тот же адаптер с новым идентификатором, у всех подключений, закреплённых за ним. Если адаптер найти не удалось, в статусе появляется понятное предупреждение, а не молчаливая блокировка сети.
- Частные сети, назначенные туннелю "остального интернета", блокируются, пока он не поднят, и не уходят в локальную сеть.
- Ручное отключение основного подключения в режиме "Разрешить всё" больше не считается обрывом: его трафик остаётся заблокированным, как и пишет статус.
- Адреса проверки отзыва сертификата открываются только на время подъёма подключения и только для TCP на порт из ссылки.
- Временные ошибки телефонной книги Windows больше не останавливают переподключение.
- Повреждённый файл состояния службы больше не снимает защиту.

## AnyConnect

- Помощник, не получивший сеанс за 90 секунд без действий пользователя, останавливается. Новый помощник ждёт выхода прежнего, а служба при остановке ждёт, пока все помощники попрощаются со шлюзом.
- Переподключение после обрыва сети внутри сеанса - до 5 минут без нового входа.
- Свой профиль встроенного браузера у каждого подключения; смена группы в форме входа работает; переключатель прокси не требует нового входа.
- Понятная ошибка для сертификатов с ключом в CNG или TPM. Копии сертификата для помощника обновляются при продлении и удаляются, когда сертификат больше не выбран ни в одном подключении.
- Публичные зоны вроде com.ru из split DNS шлюза не уходят в список поиска DNS и не направляются к DNS шлюза.

## Прочее

- Установка обновления, которую окно программы перестало ждать, больше не запускается позже.
- Каталог данных ProgramData\SplitVpn создаётся с закрытыми правами; подложенные чужие файлы откладываются, а не принимаются.
- Установщик сверяет библиотеки OpenConnect с хешами из репозитория.
- Слишком большой файл ручного импорта базы (больше 2 МБ) даёт понятную ошибку, а не "служба недоступна".

## Важно при обновлении

- **Свёртка списка обхода.** Новое значение по умолчанию (/18) действует только для новых установок, при обновлении остаётся /24. Чтобы маршрутов стало меньше, выберите в "Настройках" пункт "Объединять адреса в подсети" со значением /18 и нажмите "Сохранить". Перезапуск службы не нужен.
- **Закреплённый адаптер.** Описание адаптера служба запоминает при первой сверке после обновления. Если сеть Windows сбросили раньше и статус пишет "Закреплённый основной адаптер не найден", выберите адаптер заново в настройках подключения.
- **AnyConnect.** Профили встроенного браузера теперь у каждого подключения свои: для второго и следующих подключений вход в SSO организации понадобится один раз заново.
- **Цели проверки туннеля.** Сохранённые цели не меняются. Чтобы добавить вторую, допишите в настройках `"foreign": "1.1.1.1:443, 1.1.1.1:80"`.

## Состав и установка

Служба Windows, интерфейс WPF и трей, помощник AnyConnect. Поддерживаются SSTP, L2TP/IPsec, IKEv2, PPTP и Cisco AnyConnect. Требуется Windows 11 x64; .NET 10 входит в поставку.

Перед обновлением закройте "Раздельный VPN", в том числе через меню значка в трее. Установщик обновляет интерфейс и службу вместе, сохраняя настройки и подключения:

```
msiexec /i SplitVpn-0.15.3.msi
```
