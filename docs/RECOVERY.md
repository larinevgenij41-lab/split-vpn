# Восстановление сети

Программа меняет три вещи в системе: маршруты (с меткой-метрикой 3917), фильтры WFP (свой провайдер «SplitVpn») и DNS адаптеров (на 127.0.0.1, исходные сохраняются). Всё это снимается тремя способами, от простого к аварийному.

## 1. Из приложения

**Главная → «Отключить и восстановить интернет»** — штатный путь. Или **Диагностика → «Восстановить сеть»**: то же самое, но работает и когда служба недоступна — тогда приложение запускает `SplitVpn.Service.exe recover` с правами администратора.

После восстановления служба помечает защиту приостановленной и ничего не применяет, пока вы не нажмёте «Подключить»; на главной в это время кнопка «Подключить» и текст «Защита снята восстановлением сети». Если восстановление шло без службы (с запросом прав администратора), служба остановлена и сама не запустится до перезагрузки: **Диагностика → «Запустить службу»**, затем «Подключить».

## 2. `recover-network.cmd`

Ярлык лежит на рабочем столе (или `scripts\recover-network.cmd` в папке программы). Запросит права администратора и:

1. выполнит `SplitVpn.Service.exe recover`: приостановит защиту, остановит службу без автоперезапуска, разорвёт VPN, снимет маршруты, вернёт исходный DNS (только там, где всё ещё стоит наш 127.0.0.1 — вашу ручную настройку не тронет), удалит все объекты WFP, сбросит кеш DNS;
2. если штатный путь недоступен — сделает то же встроенными средствами Windows: удалит маршруты с меткой 3917, сбросит DNS интерфейсов, где стоит только 127.0.0.1, разорвёт соединения RAS программы, переведёт службу в ручной запуск. Фильтры WFP встроенными средствами не снять — тогда нужна перезагрузка: служба не в автозапуске, и фильтры не загрузятся.

Команду можно выполнять несколько раз подряд — повторный запуск ничего не портит.

## 3. Если совсем ничего не работает

- Служба в ручном запуске (`sc config SplitVpn start= demand`) + перезагрузка: постоянные фильтры провайдера, чья служба не в автозапуске, BFE не загружает.
- Удаление программы также выполняет `recover --uninstall`.

## Что происходит при сбоях без вашего участия

| Ситуация | Поведение |
|---|---|
| Служба упала | Windows перезапустит её (5 с / 5 с / 5 с, счётчик сбрасывается через сутки); защита и VPN в это время сохраняются, новая служба их подхватывает без дозвона |
| Непредвиденная ошибка в службе | служба завершается с ненулевым кодом и перезапускается диспетчером служб; защита (постоянные фильтры) при этом остаётся |
| Повреждён служебный файл (состояние, база, сохранённый DNS, пароли) | файл уводится в копию «имя.corrupt-дата», служба стартует со значениями по умолчанию, в журнале и на главной — предупреждение; сохранённые пароли, если это они, вводятся заново |
| Обрыв VPN | трафик, назначенный VPN, блокируется (или по вашей настройке), повторное подключение с нарастающей паузой до 60 с |
| Нет интернета в туннеле (проверка не проходит) | туннель переподключается с растущей паузой; в событии — число попыток и вероятная причина (например, активное VPN-подключение Windows) |
| Неверный пароль или ошибка сертификата | повторов нет, состояние «Ошибка», защита остаётся |
| Пропал основной адаптер (Wi-Fi выключен) | «Трафик заблокирован», после появления сети — переподключение |
| Кто-то удалил наш маршрут, фильтр или сменил DNS | восстанавливается не позже чем через 60 с, событие в журнале |
| Перезапуск службы BFE | фильтры пересоздаются |
