# Сертификаты SSTP-сервера и проверка отзыва

SSTP работает поверх TLS: Windows проверяет сертификат сервера так же, как браузер, — по хранилищу доверенных корневых сертификатов компьютера (`LocalMachine\Root`). Программа в это не вмешивается и своих исключений не добавляет.

## Сервер с сертификатом частного центра

Если сервер использует сертификат, выданный частным CA, его корневой сертификат нужно один раз добавить в `LocalMachine\Root` (например, `certutil -addstore Root ca.crt` с правами администратора). Иначе подключение завершится ошибкой категории «сертификат», и повторов не будет.

## Проверка отзыва (CRL/OCSP)

По умолчанию Windows проверяет, не отозван ли сертификат сервера. У частных CA точек распространения CRL часто нет — тогда подключение не проходит.

### Почему это ломалось за kill switch

Пока защита включена, наружу проходят только разрешённые адреса, и адрес списка отзыва в их число не входил: Windows не могла его получить и отклоняла **исправный** сертификат с ошибкой `0x80092013` («проверка отзыва недоступна»). Особенно заметно с короткими сертификатами Let's Encrypt: они обновляются раз в несколько дней, адрес списка отзыва у каждого нового сертификата свой — и подключение переставало подниматься примерно раз в неделю.

### Что делает программа (с 0.6.0)

1. Перед дозвоном и при отказе по сертификату служба **смотрит сертификат сервера** отдельной TLS-пробой: рукопожатие не доводится до конца, сеанс не устанавливается — читается только то, что сервер предъявил.
2. Из сертификата и его цепочки берутся адреса CRL и OCSP. Их узлы **открываются защитой**: имя разрешается напрямую, полученные адреса закрепляются и получают разрешающий фильтр — как обычное правило для домена «напрямую».
3. Узлы запоминаются в состоянии службы, поэтому после перезапуска открыты с первой попытки; при смене сертификата набор обновляется сам.
4. Если дозвон уже был остановлен из-за отзыва, после открытия адресов даётся одна автоматическая попытка: причина отказа к этому моменту устранена.

Сертификат сервера, срок его действия и адреса проверки отзыва видны в подробностях ошибки на главной странице и в журнале службы.

### Крайняя мера: отключить проверку отзыва

Если у сертификата сервера вообще нет рабочей точки CRL/OCSP, проверку отзыва для SSTP отключают параметром реестра
`HKLM\SYSTEM\CurrentControlSet\Services\SstpSvc\Parameters\NoCertRevocationCheck = 1`
с перезапуском службы `SstpSvc`. Программа этот параметр **не меняет** — только показывает в «Диагностике» строку «Проверка отзыва SSTP отключена системной настройкой» и приводит команду в подробностях ошибки.

**Чем это ослабляет систему:** скомпрометированный и отозванный сертификат сервера будет принят.

**Как вернуть проверку:** удалить параметр (или установить 0) и перезапустить службу `SstpSvc` либо перезагрузить компьютер.
