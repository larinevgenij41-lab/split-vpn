Выпуск по итогам полного код-ревью: исправлены уязвимости защиты и обновления, ошибки DNS-посредника, подключения нескольких туннелей и интерфейса. Ускорены доменные маршруты, обновление фильтров WFP и DNS-кеш.

## Безопасность

- Адреса проверки отзыва сертификата сервера открываются в обход защиты только из доверенной цепочки, выданной на имя сервера, и только на точное имя. Ранее выученные адреса из непроверенных сертификатов отбрасываются.
- DNS-посредник занимает и `::1`; адаптеру этот адрес назначается, только если посредник его действительно слушает.
- Каталог данных службы проверяется при запуске: чужой владелец или ссылка вместо каталога не принимаются. Каталог обновлений не работает через ссылки.
- Канал управления получает случайное имя при каждом запуске; посторонние подключения отклоняются сразу, до первого запроса.
- Манифест обновления подписывается со сроком годности; старый манифест без срока не может «заморозить» обновления. Зеркала пробуются, если основной адрес отдал неверную подпись или пакет.
- Сохранённые пароли защищаются DPAPI учётной записи службы (переход автоматический).
- Помощник AnyConnect не читает посторонний конфиг GnuTLS и прерывает запуск при ошибке инициализации PKCS#11.

## Исправления

- Пароль «до перезапуска» хранится для каждого подключения отдельно.
- «Проверить адрес» больше не зависает на доменах с правилами.
- Ручное отключение VPN не путается с обрывом другого туннеля или собственным разрывом службы.
- Пробное подключение профиля не обрывается плановой сверкой.
- Сбой одной команды или одного адаптера не оставляет применение незавершённым: сверка повторяется.
- Сервер без промежуточного сертификата подключается при включённой защите.
- Большие DNS-ответы усекаются по размеру буфера клиента (TC), DNSSEC-ответы кешируются отдельно; если TCP-порт 53 занят другой программой, посредник работает по UDP.
- Собственный резолвер пользователя на 127.0.0.1 / ::1 больше не сбрасывается при отключении; «Восстановить сеть» убирает только неработающий loopback-DNS.
- Адреса с ведущими нулями (`010.0.0.0/8`) больше не понимаются как восьмеричные. Однозначные значения в прежних настройках (`192.168.001.001`) исправляются автоматически, о неоднозначных программа предупреждает.
- Списки адресов в UTF-8 с BOM принимаются; повреждённое состояние списков восстанавливается без потери загруженных версий.
- Интерфейс: переподключение к службе после её перезапуска, сохранение профиля не затирает изменения маршрутизации, строки туннелей не пересоздаются каждые 1,5 с, ошибки формы входа видны, выключение подключения из трея переносит его назначения на «Напрямую».

## Внимание при откате

Откат на 0.9.5 без подготовки теряет сохранённые пароли: порядок описан в `docs/LIMITATIONS.md`. Если в настройках остались неоднозначные адреса с ведущими нулями, служба покажет предупреждение — исправьте их в интерфейсе.

## Состав и проверки

Windows x64: служба, интерфейс WPF, DNS-посредник, защита при обрыве, списки адресов и помощник Cisco AnyConnect. Поддерживаются SSTP, L2TP/IPsec, IKEv2, PPTP и Cisco AnyConnect.

936 автоматических тестов: 548 ядра и 388 службы (4 теста хранилища паролей требуют повышенных прав). Сценарии маршрутизации и отказов проверены на подменённых системных операциях; нативное прохождение пакетов в этом выпуске отдельно не проверялось.

## Установка

Перед установкой поверх закройте «Раздельный VPN» (`SplitVpn.exe`), затем выполните:

```powershell
msiexec /i SplitVpn-0.9.6.msi
```

Версии начиная с 0.9.1 могут получить выпуск через «О программе» → «Обновление». Для более ранних версий нужна ручная установка: они ещё не знают действующий ключ подписи обновлений.
