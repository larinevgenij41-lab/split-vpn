# Исправление производительности — 2026-09-25

Исправлены три проблемы, найденные при аудите `main`, `e7de6f0` (0.9.5).
Сохранены подтверждение маршрутов до выдачи DNS-ответа, общая транзакция WFP,
проверка внешнего удаления фильтров и разделение DNS-кеша по путям разрешения.

## Что изменено

### Повторное использование политики и адресных фильтров

Новый доменный IP раньше пересобирал адресные слои, все планы фильтров и большие
строковые отпечатки. На 10 тыс. диапазонов RU + 20 тыс. обходных диапазонов один
отпечаток 60 010 спецификаций Direct выделял 101,27 МБ.

[PolicyCompilationCache](D:/VPN/src/SplitVpn.Core/Policy/PolicyCompilationCache.cs:12)
сравнивает все входы адресной политики и при изменении только Pins переиспользует
разметку, диапазоны и CIDR. Коллекции ключа копируются, включая вложенные списки
участников групп и сетей шлюза: изменение входного списка на месте инвалидирует кеш.
Изменение состава группы, адресов серверов/DNS, правил и интерфейсных сетей требует
полной компиляции. Защита инфраструктурных IP проверяется и при обновлении Pins.

[FilterPlanCache](D:/VPN/src/SplitVpn.Core/Protection/FilterPlanCache.cs:10)
переиспользует Base и Direct. Смена основного интерфейса или параметров туннеля
инвалидирует Direct, смена LocalAccess — Base. Runtime и Dynamic строятся заново.
[Координатор](D:/VPN/src/SplitVpn.Service/Coordination/Coordinator.Apply.cs:543)
сравнивает сами спецификации и условия; строковые отпечатки удалены. Сравнение
не зависит от отсутствия коллизий хеша. План считается применённым только после
успешной общей транзакции.

### Разностное применение доменных фильтров WFP

[SystemWfpOps](D:/VPN/src/SplitVpn.Windows/Operations/SystemOperations.cs:59)
хранит подтверждённые спецификации Dynamic и их ID. При обычном изменении только
Dynamic не перечисляет все фильтры Windows: удаляет исчезнувшие/изменившиеся
спецификации и добавляет новые. При сравнении учитываются имя, группа, действие,
семейство, вес и все условия, включая LUID, направление сравнения и порт.

Все группы по-прежнему изменяются одной транзакцией. Новый кеш ID публикуется
только после commit; abort оставляет прежний кеш. После перезапуска кеш сброшен:
неизвестные старые фильтры Dynamic сначала перечисляются и заменяются.

Полная сверка обнаруживает замену набора ID даже при прежнем количестве.
Признак необходимого восстановления сохраняется после неудачной транзакции
до успешного исправления. Для более 256 точечных проверок используется одно
перечисление фильтров вместо тысяч `FwpmFilterGetById0`; период сверки сохранён.

На подменённой нативной границе подтверждено: добавление одного IP к 1 000
закреплениям создаёт **четыре** фильтра, не удаляет прежние и не перечисляет WFP.
Раньше алгоритм требовал 4 000 удалений + 4 004 добавления. Это число операций,
не замер времени BFE.

### Индекс аварийного DNS-кеша

[DnsCache](D:/VPN/src/SplitVpn.Core/Dns/DnsCache.cs:169) находит ответ по индексу
`(Name, Type)` и выбирает свежую запись только среди путей этого имени.
Индекс обновляется под общим lock вместе с основным словарём при записи,
вытеснении и очистке. Обновление существующего ответа в полном кеше больше не
вытесняет постороннее имя. Сроки stale-ответов и разделение split-DNS сохранены.
В [DnsProxyServer](D:/VPN/src/SplitVpn.Windows/Dns/DnsProxyServer.cs:281) убран
повторный поиск при промахе и отсутствии маршрута.

## Замеры

Windows x64, .NET 10.0.12, 24 логических процессора, Release, tiered compilation
отключена. Медиана пяти серий после 20 прогревочных операций. МБ = 1 000 000 байт;
аллокации измерены через `GC.GetAllocatedBytesForCurrentThread`, это не постоянный
рабочий набор процесса. Все измеряемые операции синхронные.

| Операция | До | После | Аллокации до → после |
| --- | ---: | ---: | ---: |
| Политика и планы: 10 тыс. RU + 20 тыс. обхода, изменение одного IP при 1 000 Pins | 85,087 мс | 0,303 мс | 155,45 → 0,807 МБ |
| AnyPath: попадание, 10 000 записей DNS | 788,149 мкс | 0,185 мкс | 768 → 304 байт |
| AnyPath: промах, 10 000 записей DNS | 279,225 мкс | 0,047 мкс | 528 → 0 байт |

Для политики старый и новый алгоритмы выполнены на одинаковых входах в одном
запуске: по очереди добавляется/удаляется один pin. Старая сборка планов использует
сохранённое в утилите выражение `FilterFingerprint` из `e7de6f0`. Новая выполняет
реальные классы кеша и структурное сравнение. Для DNS «до» — исходный запуск аудита,
«после» — повторный запуск на той же машине. До исправлений аудит вызывал настоящий
приватный метод отпечатка через заранее созданный делегат; после его удаления
историческое выражение оставлено только в утилите замеров.

Обновление политики и планов при 10 000 Pins занимает 10,87 мс и выделяет 8,28 МБ:
построение Dynamic остаётся линейным по числу закреплений. Время начальной полной
компиляции и построения Direct существенно не изменилось. Измерения выше не
включают `PromotePins`, применение маршрутов/WFP, конкуренцию DNS-клиентов и сеть.

```powershell
dotnet run --project tools/PerformanceAudit/PerformanceAudit.csproj -c Release
```
