### Отклонение: калибровка порогов аномалий

План требовал рассчитать пороги по 8–12 прошлым ревизиям. Это невозможно: ветка `release` репозитория Loyalsoldier/geoip перезаписывается одним коммитом (API коммитов по пути `text/ru.txt` возвращает одну ревизию), а в GitHub Releases публикуются только `.dat` и `.mmdb`. Приняты пороги по умолчанию — изменение покрытия адресов более 10 % или числа диапазонов более 20 % отправляет обновление на ручное подтверждение. Служба записывает фактические изменения каждой проверки; пороги пересматриваются по накопленным данным.

### Решения по итогам КТ1

- Фильтры Direct — вариант A (диапазон на фильтр) с `FWPM_FILTER_FLAG_INDEXED`. Вариант B и сверка по разнице не нужны.
- DNS-посредник — `127.0.0.1:53` с `SO_EXCLUSIVEADDRUSE` от SYSTEM; запасной `[::1]` не понадобился.
- DNS PPP — вариант (b): в записи RAS `RASEO_SpecificNameServers` = 127.0.0.1. DNS, выданный сервером, приходит в реестр туннеля до переопределения только в варианте (a), поэтому upstream по умолчанию берётся из первого подключения без переопределения либо задаётся пользователем (решается в КТ2).
- Upstream DNS через туннель — только `IP_UNICAST_IF`; работает, пока на туннеле есть `/1` (состояние Connected). Без туннеля запрос не уходит, утечки нет.
- RAS сам ставит `/32` к серверу через шлюз основного адаптера; свой `/32` оставляем (идемпотентно).
- sing-box не нужен: системная схема удовлетворяет всем требованиям КТ1.
- Исключения CA для проверки отзыва — пусто (у сервера нет CDP/AIA; отзыв отключён системной настройкой).

### Находки

- `IP_UNICAST_IF` не обходит маршрутизацию: нужен маршрут на выбранном интерфейсе, иначе `NetworkUnreachable`.
- Постоянные маршруты с интерфейсом «любой PPP» включаются на туннеле любого RAS-соединения. Детектор конфликтов (КТ4) должен их показывать.
- Для неподключённого UDP-сокета блокировка WFP не возвращает ошибку `sendto` — датаграмма молча отбрасывается. Проверять по ответу или по счётчикам pktmon.
- `pktmon counters --json`: массив групп `{Group, Components[{Name, Counters[{Name, Type, Inbound, Outbound}]}]}`; у счётчиков сбросов есть поле `Last Drop Reason`.
- `GetInterfaceDnsSettings` возвращает `ERROR_FILE_NOT_FOUND` для интерфейсов без DNS-настроек (loopback, Teredo) — это «нечего восстанавливать».
- В .NET 10 `IPNetwork.TryParse` принимает подсеть с битами хоста, молча обнуляя их.

### Отклонения от плана КТ1

- Очистка dev-окружения (`cleanup-dev.ps1`) перенесена на начало КТ2: dev-утилита и профиль прототипа нужны для сравнения со службой; секрет прототипа удаляется там же.

### Исправленные ошибки

1. Клиент IPC запрашивал `GENERIC_WRITE` — канал с минимальным ACL отказывал; открытие с явными `PipeAccessRights`.
2. Проверка сервера через `OpenProcess` недоступна без повышения — заменена на SCM (PID службы, путь образа, LocalSystem).
3. Сервер олицетворял клиента до чтения и отвечал с нулевыми буферами — взаимная блокировка; сначала первый кадр, буферы 64 КБ; проверка групп вне олицетворения (иначе `FileNotFoundException` при загрузке сборки).
4. Неверный URI claim deny-only SID — `ClaimTypes.DenyOnlySid`.
5. Удаление отсутствующего sublayer/провайдера WFP (0x80320007/0x80320005) давало «Неполное применение» при старте с намерением Off.
6. Подхват после перезапуска: адрес сервера появлялся только после первой сверки — снимались /32 и разрешение к серверу, SSTP рвался. Адрес теперь загружается до сверки (IP из профиля или сохранённый).
7. `ForceProtection` сбрасывался до сверки маршрутов — удалённые извне маршруты не восстанавливались; удалённые фильтры не обнаруживались (проверялось только наличие группы) — теперь сравнение числа фильтров по группам.
8. Внешний DNS при коррекции дрейфа перезаписывал сохранённый исходный DNS.
9. После неудачного дозвона запись оставалась занятой (756) — перед дозвоном разрываются остатки соединений своей записи.
10. Выключение «сохранять пароль» или удаление профиля оставляло сохранённый секрет — теперь удаляется.
11. Валидатор настроек не принимал «хост:порт».

### Инцидент 2026-09-13 13:09 — потеря нероссийского интернета на ~10 минут

- **Причина:** сценарий `switch-profile` читал JSON настроек через `Get-Content -Raw` без `-Encoding UTF8` (Windows PowerShell 5.1 читает ANSI): имена профилей превратились в мусор, `activeProfileId` стал `null`. Служба приняла такие настройки, разорвала VPN («изменены параметры подключения») и не могла дозвониться — профиля нет. Намерение «Подключено» с включённой защитой = kill switch без выхода. Сценарий на неудаче не снял защиту. Перезапуски службы и перезагрузка состояние не меняют (так задумано); предохранитель «при загрузке» в 13:17:28 снял фильтры; `recover-network.cmd` пользователя завершил восстановление.
- **Исправлено:** валидатор отклоняет настройки без активного подключения при наличии профилей (тест); намерение «Подключено» без профиля даёт состояние «Ошибка» с подсказкой, а не бесконечное «Подключение» (тест); сценарии читают JSON в UTF-8 и при невозможности восстановить подключение снимают защиту («Отключить и восстановить интернет»); `switch-profile` переключает активный профиль до удаления копии.
- **Урок:** любой автоматический сценарий обязан заканчиваться либо проверенным «Подключено», либо снятой защитой; данные, идущие в службу из скриптов, — только через UTF-8.

### Сборка

- В репозиториях MSYS2 пакета OpenConnect больше нет (packages.msys2.org, 2026-09-14). libopenconnect 9.21 собрана из официального архива (SHA-256 `5b32369467db6e5f317aa1ed12cfcbb81ed00bdbc765450b6bfcbdc300944a58`) в MSYS2 UCRT64 скриптом `scripts\build-openconnect.sh`.
- Правка исходника: `compat.c` подключает `sec_api/stdlib_s.h`, которого нет в новых заголовках mingw-w64; заменяется на `stdlib.h`.
- Конфигурация: GnuTLS с `gnutls_system_key_add_x509` (ключи из хранилища Windows), DTLS, HPKE/STRAP, Wintun 0.14.1 (скачивается сборкой). Без stoken, pcsclite, libproxy, GSSAPI.
- Замыкание: `libopenconnect-5.dll` + 19 DLL UCRT64 (gnutls, nettle, hogweed, gmp, p11-kit, libxml2, zlib, lz4, zstd, brotli×3, idn2, unistring, tasn1, intl, iconv, ffi, winpthread) + `wintun.dll` + `ocshim.dll`.
- `wintun.dll` библиотека грузит только из каталога exe (`LOAD_LIBRARY_SEARCH_APPLICATION_DIR`), остальные DLL — через `SetDllDirectory`.

### Выводы для плана

- Сеанс ASA живёт только в экземпляре библиотеки. Хранить cookie между процессами бессмысленно: рестарт службы, обновление и падение помощника требуют нового входа (при запомненном ADFS — несколько секунд без ввода, но нужен пользовательский сеанс с App).
- При остановке — `CANCEL` (BYE), а не detach.
- Смена сети и обрывы переживаются внутри помощника (`mainloop` сам переподключается; паузу можно использовать для явного переподключения).
- Сетевые параметры брать из `ip_info` (MTU, split DNS, PAC), срок — из заголовка сессии.
- Широковещательные /32 Windows на туннеле не считать чужими маршрутами.
