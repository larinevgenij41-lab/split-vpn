Windows теперь может сама проверить интернет на основном адаптере при включённой защите. Раньше эта проверка не проходила никогда: Windows отправляет её запрос DNS с привязкой к адаптеру, а программа ставила адаптеру сервер DNS 127.0.0.1, до которого такой запрос не доходит (ошибка 10049). Проверка зависала на 30-35 секунд и повторялась по кругу. Вероятное следствие: после загрузки служба автонастройки WLAN считала подключение Wi-Fi ограниченным, на 32-й секунде перезапускала драйвер адаптера, а через минуту отключала Wi-Fi ещё на полминуты (событие 4003 в журнале "Система"). Оба раза обрывались все подключения VPN.

Теперь DNS-посредник программы отвечает и на адресе самого адаптера, а основному адаптеру ставится список DNS "свой адрес, 127.0.0.1". Запрос, привязанный к адаптеру, доходит до первого адреса. Второй адрес работает, если адрес адаптера сменился, а список ещё не обновлён.

Посредник отвечает только программам этого компьютера: запросы из локальной сети он отбрасывает. Чужим резолверам на других адаптерах (DNS WSL, Hyper-V, общий доступ к интернету) он не мешает: их адреса остаются за ними. Если порт 53 на всех адресах занять не удалось, остаётся прежний одиночный 127.0.0.1, и в журнале появляется предупреждение.

При отключении защиты, остановке службы, удалении программы и аварийном восстановлении сети (`recover-network.cmd`) новый список распознаётся как поставленный программой, и адаптеру возвращается его прежний DNS.

В поставку входят служба Windows, графическое приложение, помощник OpenConnect и движок SSH. Поддерживаются SSTP, L2TP/IPsec, IKEv2, PPTP, Cisco AnyConnect и VPN поверх SSH (TCP).

Перед установкой поверх прежней версии закройте SplitVpn.exe. Во время обновления служба перезапустится. Команда установки

```powershell
msiexec /i SplitVpn-0.17.9.msi
```
