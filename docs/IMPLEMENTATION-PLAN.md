# План реализации «Раздельный VPN» (SplitVpn) — SSTP-клиент Windows с разделением RU/VPN

## Контекст

В `D:\VPN` лежат только требования: `PLAN.md` (функциональный план, этапы 1–7, матрица приёмки §10) и `RESEARCH.md` (RU-базы и порядок автообновления). Кода и git нет. Задача — разработать приложение до v1. Состав: встроенный SSTP Windows через RAS, служба управления маршрутами и WFP-защитой, локальный DNS-посредник, автообновляемая RU-база, WPF-интерфейс на русском, MSI.

Решения пользователя (2026-09-12):
1. Весь код до v1, по контрольным точкам (КТ). На непройденной КТ работа останавливается.
2. Админ-шаги — через `Start-Process -Verb RunAs` с подтверждением UAC и логом в файл; испытания на этом ПК.
3. Kill switch на persistent WFP: защита переживает падение службы, сон и перезагрузку (с момента старта BFE). Boot-time фильтров нет, аварийное восстановление обязательно.
4. Личное использование: без подписи кода, MSI, ручное обновление, атрибуция Loyalsoldier/GeoLite2.

План прошёл критику тремя субагентами (опровержение, полнота, KISS); замечания учтены ниже. Рабочее имя — `SplitVpn`, в интерфейсе «Раздельный VPN».

## Архитектурные решения

- **Стек.**
  - .NET 10 LTS (поддержка до 2028-11-14), SDK 10.0.4xx через `global.json`; сборка только `dotnet` CLI.
  - Interop: `Microsoft.Windows.CsWin32`; если генерация даёт сбой — точечные `[DllImport]` в одном файле.
  - UI: WPF + CommunityToolkit.Mvvm + WPF-UI 4.3 (Fluent, NavigationView, темы) + H.NotifyIcon.Wpf.
  - Serilog (файл), xunit.v3.
  - WixToolset.Sdk 7: OSMF EULA бесплатна для личного использования; `AcceptEula` принимает пользователь.
  - Версии пакетов закрепляются в `Directory.Packages.props` и сверяются с NuGet на КТ0.
- **Модель службы «намерение → сверка».**
  - Координатор хранит намерение: `Off` / `Protected` / `Connected`, режим разделения, режим обрыва, флаг `ProtectionSuspended`. Намерение сохраняется в настройках.
  - Также хранятся факты: основной адаптер, IP сервера, RAS-соединение, туннель, активная база, состояние BFE.
  - Любое событие (IPC, RAS, сеть, BFE, таймер, база) попадает в один актор на `Channel<T>`, обновляет факты и вызывает `Reconcile()`. Цепочка идемпотентных шагов `Ensure*` описана в разделе «Последовательности».
  - Отдельных классов потоков нет. Старт службы — это чтение фактов и `Reconcile()`.
- **Опознание своих объектов без журнала.**
  - Маршруты — по метке-метрике (например, 3917) и ключу (префикс, LUID, next hop).
  - WFP-объекты — по ключу провайдера; RAS-записи — по своему pbk.
  - Маршруты /1 исчезают вместе с интерфейсом.
  - Сохраняется только то, что нельзя восстановить из системы: `DnsBackup` — исходные `NameServer`, `ProfileNameServer` и DoH-свойства по InterfaceGuid (DNS_INTERFACE_SETTINGS3). Запись атомарная: временный файл и `File.Move(overwrite)`.
  - Системные действия журналируются в Serilog.
- **WFP: persistent — только фильтры, зависящие от настроек.** Всё, что зависит от сети и времени выполнения (IP сервера, DNS, LUID, Direct-диапазоны, режим обрыва), — static; эти фильтры ставит служба. После перезагрузки система закрыта строже: RU тоже заблокирована, пока служба не стартует. Вариант с persistent Direct не рассматривается.
- **Изменение группы фильтров — одна транзакция WFP:** удалить группу, добавить новую, commit; при ошибке abort. Группы: База (persistent), Direct (static), Рабочие (static). Id фильтров хранятся в памяти. При старте службы и при переходе BFE в RUNNING static-группы пересоздаются. Сверка по разнице — только если замер КТ1 превысит ориентир.
- **Компилятор политики — только IPv4.**
  - Строки IPv6 базы разбираются и считаются для UI.
  - Пользовательские правила IPv6 отклоняются с сообщением «IPv6 ограничен в этой версии».
  - Публичный IPv6 блокируется.
- **Секреты:** `ProtectedData` LocalMachine + entropy. Файл `%ProgramData%\SplitVpn\secrets.bin`; ACL — только SYSTEM и Administrators, наследование отключено. Один механизм для прототипа и продукта.
- **Проверка отзыва сертификата:** реестр не трогаем. В «Диагностике» — строка «Проверка отзыва SSTP отключена системной настройкой». В `docs/CA-TRUST.md` — чем это ослабляет систему и как вернуть. Категория «ошибка сертификата» определяется по коду RasDial.
- **Hyper-V/WSL (NAT) и раздача VPN** вне объёма (PLAN §1). Фактическое поведение при обрыве фиксируется в `LIMITATIONS.md`.

## Компоненты

### SplitVpn.Core
- `Net/RangeSet` — разбор через `System.Net.IPNetwork.TryParse`, диапазоны `(uint start, uint end)`, union и subtract, слияние только точно смежных, `CidrCover` для точного покрытия.
- `Policy/PolicyCompiler` — «покраска» от низшего приоритета к высшему:
  1. default VPN;
  2. гео Direct (пропускается в режиме «весь через VPN»);
  3. пользовательские правила по возрастанию длины префикса;
  4. локальные и спецдиапазоны, в том числе on-link-префиксы интерфейсов;
  5. IP серверов.

  `PolicyValidator` отклоняет: одинаковый префикс с разными действиями; Block, пересекающийся со служебными адресами (инвариант с property-тестом). Выход `CompiledPolicy`: `DirectRanges` (WFP), `DirectRouteCidrs`, `LocalRanges`, `BlockRanges`, `Classify(ip) → (действие, источник)`.
- `Geo/` — модули базы:
  - `GeoListParser`;
  - `GeoValidator` — HTML, пустой набор, 0/0 и ::/0, биты хоста, спецдиапазоны, дубликаты, пустое семейство;
  - `GeoDiff` — число и покрытие, пороги аномалий;
  - `GeoStore` — active / previous / pending, пометка `Skipped` для ревизии после отката или импорта, метаданные: источник, URL, SHA-256, дата данных, дата загрузки, v4/v6;
  - источники: `LoyalsoldierSource` (GET `raw…/release/text/ru.txt` с If-None-Match; один файл v4+v6, поэтому смешения ревизий нет; версия — SHA-256), `IpverseSource` (JSON, режим «страна регистрации»), `CustomUrlSource` (текст CIDR по HTTPS) и список зеркал той же базы.

  Смена источника — только с показом разницы.
- `Dns/DnsMessage` — заголовок, вопрос, обход RR ради минимального TTL, подмена ID/TTL в сырых байтах; OPT пересылается как есть. `DnsCache` — ключ qname+qtype, только в памяти; в режиме Offline отдаёт кешированные ответы с TTL 30 с. Адреса SSTP-сервера — записи без истечения.
- `Settings/` — `schemaVersion: 1`. Неизвестная версия — ошибка с предложением сбросить; перед импортом — `.bak`.
  - Профиль: имя, сервер, пользователь, `Domain?`, `AuthMethod` (в v1 только MsChapV2), `SavePassword`, `PrimaryAdapter = Auto | Pinned(InterfaceGuid)`, `AllowFallbackWhenPinnedMissing`, `Retry`.
  - Глобальные настройки: режим разделения; режим обрыва (VPN-трафик / весь публичный / разрешить всё); `DnsDirectOnOutage` (по умолчанию выкл); `LocalAccess` (по умолчанию вкл); локальные суффиксы и DNS; upstream DNS; автоподключение; `GeoUpdate {AutoUpdate, IntervalDays ∈ {1,3,7}, Source, Mirrors, DeferOnMetered}`; цели проверки.
  - Время — в UTC.
- `State/` — состояния PLAN §6 плюс «VPN отключён извне», «Требуется пароль», «Неполное применение». `Backoff`: 1→60 с, ±20 %. `RasErrorClassifier`: без повторов — 691 и ошибки сертификата, остальные — повтор.
- `Ipc/` — только запрос/ответ, кадр `uint32 длина + UTF-8 JSON`, лимит 2 МБ.
- `StatusText.Format(StatusDto)` — строка вида «Россия → Беспроводная сеть · Остальные адреса → VPN · Защита включена».
- `Redactor` — маскирует пользователя, сервер, IPv4/IPv6, MAC, GUID; применяется к отчёту и dev-отчётам.

### SplitVpn.Service
- `Program.cs` — `run` и `recover [--uninstall]`. `PowerAwareLifetime` — сон и гибернация. `BfeWatcher` — NotifyServiceStatusChangeW на BFE; любая RPC-ошибка Fwpm* или переход в RUNNING → переоткрыть движок и выполнить Reconcile. Периодический Reconcile — раз в 60 с (восстанавливает изменения DNS, маршрутов и фильтров, сделанные извне).
- `Coordinator` — актор и шаги `Ensure*` (каждый со сложностью ≤ 8).
- `IpcServer`:
  - канал создаётся через `CreateNamedPipe` с `PIPE_REJECT_REMOTE_CLIENTS` и обёрткой `NamedPipeServerStream(SafePipeHandle)`;
  - ACL: SYSTEM Full, Administrators RW, INTERACTIVE — ReadData, WriteData, ReadAttributes, Synchronize (без CreatePipeInstance), Deny NETWORK;
  - проверка клиента: `GetTokenInformation(TokenGroups)` — S-1-5-32-544, в том числе с SE_GROUP_USE_FOR_DENY_ONLY, плюс INTERACTIVE;
  - клиент до отправки команд проверяет сервер: `GetNamedPipeServerProcessId` → SYSTEM и путь образа службы;
  - команды: GetStatus, GetEvents(since), GetAdapters, GetSettings, SaveSettings (профили, правила, режимы), SetPassword, Connect(password?), Disconnect(keepProtection), SwitchProfile, TestProfile, CheckAddress, GeoUpdateNow, GeoImport(содержимое), GeoRollback, GeoAcceptPending, GeoRejectPending, ExportReport, RecoverNetwork.
  - Сообщения с паролем исключены из деструктуризации Serilog.
- `DnsProxy/DnsProxyServer`:
  - адрес по итогам КТ1; UDP bind с `SO_EXCLUSIVEADDRUSE`; TCP bind с фоновыми повторами, его отказ не фатален;
  - режим Online — upstream через туннель только по `IP_UNICAST_IF` (loopback как upstream запрещён);
  - режим Offline — кеш и закреплённые записи, иначе SERVFAIL;
  - «DNS напрямую при обрыве» (или режим «разрешить всё») — исходный DNS через разрешение app-id службы;
  - локальные суффиксы → DNS LAN;
  - qname не пишется в журналы уровня Information и выше.
- `DnsProxy/BootstrapResolver` — запрос к актуальному `DhcpNameServer` или статическому исходному DNS основного адаптера; возвращает все A-записи; повторное разрешение — по TTL и после 3 неудачных переподключений.
- `Geo/GeoUpdateWorker`:
  - запуск при старте, по интервалу ± jitter, после восстановления сети при пропущенном сроке, по команде; один активный запрос на источник; backoff; 403/429 → ждать `Retry-After`;
  - сетевой путь: при `Off` — напрямую, в UI «через обычное подключение»; при `Connected` — через туннель; при `Protected` или Reconnecting — перенос до `Connected`;
  - в лимитной сети фоновая загрузка откладывается (`NetworkInformation…GetConnectionCost`), ручная доступна.

## Схема WFP

- Провайдер persistent, `serviceName="SplitVpn"`; служба в режиме обычного Auto, не delayed.
- Sublayer persistent, вес 0xFFFF.
- Фильтры ставятся на ALE_AUTH_CONNECT и ALE_AUTH_RECV_ACCEPT V4/V6. Разрешения мягкие, блоки жёсткие.
- Вес внутри sublayer — FWP_UINT8; срабатывает фильтр с наибольшим весом.

| Вес | Действие | Условия | Жизнь | Когда |
|---|---|---|---|---|
| 15 | Permit | loopback | persistent | всегда |
| 14 | Block | remote ∈ пользовательские Block | persistent | политика вкл |
| 13 | Permit | DHCPv4 (UDP local 68 ↔ remote 67), DHCPv6 (546↔547), ICMPv6 ND 133–137 | persistent | всегда |
| 13 | Permit | TCP к IP сервера :443 AND IP_LOCAL_INTERFACE = основной адаптер | static | политика вкл |
| 13 | Permit | ALE_APP_ID службы AND ALE_USER_ID = SYSTEM → исходный DNS и DNS LAN :53 | static | политика вкл |
| 12 | Permit | IP_LOCAL_INTERFACE = LUID туннеля (весь трафик, включая DNS) | static | туннель поднят |
| 11 | Block | remote port 53 UDP/TCP — DNS-страж | persistent | политика вкл |
| 10 | Permit всё | — | static | обрыв + режим «разрешить всё» |
| 9 | Permit | remote ∈ RFC1918 ∪ 169.254/16 ∪ 224/4 ∪ 255.255.255.255 ∪ fc00::/7 ∪ fe80::/10 ∪ ff00::/8 | persistent | LocalAccess вкл |
| 9 | Permit | remote ∈ on-link-префиксы ≥ /8 интерфейсов (кроме туннеля) | static | LocalAccess вкл |
| 8 | Block | IP_LOCAL_INTERFACE ≠ основной адаптер (без адаптера — без условия) | static | политика вкл |
| 7 | Block всё | — | static | обрыв + режим «блокировать весь публичный» |
| 6 | Permit | remote ∈ DirectRanges (FWP_RANGE) | static (группа Direct) | «Россия напрямую»; в «весь через VPN» — только ручные Direct |
| 0 | Block | всё, V4 и V6 | persistent | политика вкл |

- **Подключение туннеля** — одна транзакция: добавить фильтр 12, удалить 7 и 10. **Обрыв** — наоборот.
- В режиме «разрешить всё» DNS-страж остаётся. Системный DNS идёт через посредник к исходному DNS (режим подразумевает прямой DNS). Приложения с жёстко заданным DNS блокируются — это ограничение.
- **IPv6 v1:** разрешений Direct и туннеля для v6 нет, статус «IPv6 ограничен».
- **Проверяется в КТ1 (S3):** `FWP_MATCH_NOT_EQUAL` по LUID и условие интерфейса при переавторизации на RECV_ACCEPT. Если условие пустое — запасной вариант: убрать фильтр 8 и задокументировать, что RU при пропаже основного адаптера может уйти через другой интерфейс с 0/0; для VPN-назначений утечки нет.

## Последовательности

**Reconcile (намерение Protected или Connected):**
1. `EnsureRoutes` — /32 серверов и `DirectRouteCidrs` через шлюз основного адаптера, по разнице с меткой. Поведение совпадает с маршрутом по умолчанию, поэтому шаг идёт до WFP.
2. `EnsureProtection` — группа База при необходимости; группы Рабочие и Direct по фактам.
3. `EnsureDns` — посредник запущен в нужном режиме, закреплённые записи сервера; DNS адаптера — loopback (с DnsBackup); сброс кеша DNS при изменении.
4. `EnsureDial` — только при намерении Connected и отсутствии соединения: EnumConnections → RasDial с backoff; результат приходит событием.
5. `EnsureTunnel` — транзакция «добавить 12, удалить 7/10»; /1 на LUID туннеля; DNS PPP по варианту КТ1; посредник Online.
6. `Verify` — GetBestRoute2 на выборке, DNS через upstream, TCP 443 к иностранной цели через туннель и к RU напрямую (5 с) → Connected; при провале — HangUp и повторный дозвон, без цикла на ссылке.

**Отказ шага:** состояние «Неполное применение: <шаг, код Win32>», База остаётся, Reconcile повторяется с backoff, в UI кнопка «Восстановить сеть». Намерение `Off` при отказе снятия — то же сообщение.

**Намерение Off** («Отключить VPN и восстановить обычный интернет»): HangUp → удалить маршруты по метке → вернуть DNS («сравнить и вернуть»), очистить NameServer PPP → остановить посредник → одна транзакция: все фильтры, sublayer и провайдер. Защита снимается последней.

**Protected** («Отключить, сохранить защиту»): HangUp → транзакция «удалить 12, добавить фильтр режима обрыва» → посредник Offline.

**Обрыв:** RAS пропал без нашего HangUp.
- Если отключено из меню сети Windows (намерение было Connected, ошибки RAS нет) — «VPN отключён извне, защита сохранена», одно уведомление; повтор только при включённом автоподключении.
- Иначе — Reconnecting: фильтр режима обрыва, посредник Offline, повтор с backoff. 691 или ошибка сертификата — Error без повторов.

**Смена сети, сон, гибернация:** после антидребезга — Reconcile. Сменился адаптер или шлюз → HangUp, DnsBackup нового адаптера, переразрешение сервера, пересоздание группы Рабочие, перенос маршрутов, дозвон. Закреплённый адаптер пропал → без fallback «Трафик заблокирован: адаптер <имя> недоступен», с fallback — выбор как в Auto с предупреждением.

**Смена профиля или политики на лету:** SaveSettings/SwitchProfile → компиляция → Reconcile (группа Direct целиком, маршруты по разнице, сброс кеша DNS). Сервер, вход и адаптер активного профиля применяются после переподключения.

**Пароль:** без сохранения пароль живёт в памяти службы до HangUp. После перезапуска службы — «Требуется пароль», защита сохраняется. Автоподключение при старте службы требует сохранённого пароля.

**Старт службы:**
1. Сразу поднять посредник, если на адаптерах loopback.
2. Установить ACL `%ProgramData%\SplitVpn` и проверить владельца.
3. Если `ProtectionSuspended` — ничего не применять.
4. Иначе — Reconcile с подхватом существующего RAS-соединения.

**recover (служба не нужна):**
1. Установить `ProtectionSuspended=true`.
2. Снять failure actions (ChangeServiceConfig2), штатный stop, при зависании TerminateProcess.
3. HangUp записей своего pbk.
4. Удалить маршруты по метке.
5. DNS — «сравнить и вернуть», без DnsBackup — сброс в DHCP только интерфейсов с DNS ровно 127.0.0.1/::1.
6. Очистить NameServer PPP-интерфейсов.
7. Удалить все WFP-объекты провайдера.
8. Сбросить кеш DNS, записать отчёт.
9. Вернуть failure actions.

Флаг снимается только действием «Подключить». Второй путь — `recover-network.cmd`: `sc stop` → `sc config start= demand` → `recover`; при ошибке — `Remove-NetRoute` по метрике, `Set-DnsClientServerAddress -ResetServerAddresses` на loopback-интерфейсах, `rasdial /disconnect`, «Перезагрузите компьютер: фильтры SplitVpn не загрузятся».

**Обновление базы:**
1. Загрузка во временный файл.
2. Валидация.
3. Разница и аномалии; при превышении порогов — ручное подтверждение, до решения работает старая база.
4. Компиляция.
5. Reconcile (Direct и маршруты).
6. Проверка → переключить указатель.

Сбой — возврат к прежней `CompiledPolicy`. Откат или импорт помечает заменённую ревизию `Skipped`. Новая RU-сеть внутри ручного VPN-правила остаётся на VPN.

**MSI:**
- Обновление: остановка службы не трогает фильтры, маршруты и RAS; `recover --uninstall` выполняется After=StopServices, Before=RemoveFiles и только при `REMOVE~="ALL" AND NOT UPGRADINGPRODUCTCODE`; новая служба подхватывает.
- Удаление: снимаются pbk, маршруты, DNS, WFP, служба, ярлыки и `%ProgramData%\SplitVpn` целиком; перед этим предлагается экспорт настроек. Ненулевой код recover прерывает удаление с сообщением «Сначала выполните „Восстановить сеть“».
- `DowngradeErrorMessage`.

### КТ5. Матрица приёмки PLAN §10
Каждая строка — процедура, доказательство (pktmon, журнал, отчёт) и результат в `docs/ACCEPTANCE.md` вместе с трассировкой требований PLAN §3–§10 и RESEARCH. КТ не закрывается, пока у какой-то строки нет статуса.

**Предусловия от пользователя** (согласуются заранее): кабель к Ethernet, точка доступа телефона с IPv6.

**Процедуры сверх КТ1–КТ4:**
- **IPv6 при IPv4-only VPN** — через точку доступа: без политики IPv6 работает; с политикой и при обрыве — отказ, pktmon v6 = 0, ND/DHCPv6 работают, в UI «IPv6 ограничен».
- **Ethernet/Wi-Fi и смена шлюза** — подключить и вынуть кабель, дом → точка доступа, закреплённый адаптер с fallback и без; pktmon на обоих NIC.
- **Локальные устройства** — LocalAccess выкл: LAN недоступна, `ipconfig /renew` работает. Вкл: LAN и суффиксы работают. То же при обрыве; mDNS/LLMNR/SSDP при выкл = 0 пакетов.
- **Несколько адресов сервера** — BootstrapResolver в тестовом режиме отдаёт {203.0.113.10, 203.0.113.20}: /32 и разрешения на оба, перебор RasMan, смена набора в Connected.
- **Пересечение правил** — широкое VPN-правило поверх RU с вложенным Direct /24, три точки.
- **Конфликты** — «Garant» при нашем Connected; Radmin; правило блокировки брандмауэра Windows к RU-адресу.
- **Hyper-V/WSL** — `nslookup` из WSL под защитой; поведение при обрыве записывается в LIMITATIONS.
- **Второй пользователь Windows** — если есть учётная запись: статус виден, команда неадминистратора отклонена.
- **Замеры** — клик → Connected, переподключение, обновление базы, CPU/RAM службы, задержка DNS p50/p95 против прямого, пропускная способность RU напрямую и через туннель. Пороги утверждает пользователь.
- **Повторная проверка** сборки Windows.

Захват на шлюзе недоступен — ограничение записано. Перед КТ5 снимается постоянный предохранитель.

## Безопасность испытаний на этом ПК

- **`elevated.ps1`** (из неповышенной сессии) запускает `Start-Process -Verb RunAs -Wait` и пишет `Start-Transcript` в `logs\`. С флагом `-AsSystem` — одноразовая задача `schtasks /ru SYSTEM`. После завершения Claude читает лог и JSON-отчёт.
- **`failsafe.ps1`** регистрирует задачу планировщика от SYSTEM с двумя триггерами: время дедлайна сценария и AtStartup. Если маркер `done` отсутствует, задача выполняет recover (exe, иначе `recover-network.cmd`); при наличии маркера задача удаляется. Предохранитель переживает закрытие окна и перезагрузку.
- **Постоянный предохранитель на КТ1–КТ4** — `%ProgramData%\SplitVpn.Dev\failsafe.armed`; проверка AtStartup и каждые 5 минут. Если служба не Running дольше 3 минут или heartbeat журнала старше 3 минут — recover. Предохранитель снимается перед КТ5.
- **Прочие страховки:**
  - dynamic-сессии WFP в S1/S3;
  - несуществующий `serviceName` в S5: перезагрузка снимает защиту;
  - `recover-network.cmd` на рабочем столе;
  - pktmon-фильтры ограничены нужными адресами и портами;
  - Redactor применяется к dev-отчётам;
  - сырые `.etl` удаляются после КТ.
- Пароль SSTP вводится только в окне консоли или приложения, в чат — никогда.

## Риски и запасные варианты

| Риск | Запасной вариант |
|---|---|
| RasDial от SYSTEM или со своим pbk не работает | pbk для всех пользователей; клон RASENTRY; трассировка RAS |
| Масштаб WFP | вариант B (OR), INDEXED, сверка по разнице; расширять RU-список нельзя (PLAN §4) |
| Порт 53 занят ICS | IPv6 ::1; схема «DNS туннеля + страж» (согласовать) |
| `NOT_EQUAL` по интерфейсу при переавторизации | убрать вес 8, задокументировать |
| Перезапуск BFE снимает static | BfeWatcher + Reconcile раз в 60 с |
| Чужое жёсткое разрешение выше нашего | «Защита не гарантирована» на главной |
| Служба убита при DNS на loopback | SCM-перезапуск, подхват, recover; утечки нет |
| Цикл службы после перезагрузки | постоянный предохранитель (КТ1–КТ4), `ProtectionSuspended`, Disabled + перезагрузка |
