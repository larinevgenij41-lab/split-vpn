# Выпуск версии

Порядок выпуска целиком выполняет `scripts\publish-release.ps1`. Раньше он существовал только как
настройка рабочей копии (`remote.origin.push = publish:refs/heads/main`) и терялся при переносе на
другой компьютер; теперь он записан в скрипте, и его шаги проверяемы.

```powershell
# 1. Поднять <Version> в Directory.Build.props и закоммитить (в сообщении коммита — версия в скобках).
# 2. Собрать нативные библиотеки AnyConnect, если каталог third_party\openconnect\bin пуст.
# 3. Выпустить:
scripts\publish-release.ps1 -NotesFile docs\notes-0.8.0.md
```

Что делает скрипт:

1. **Проверки.** Версия совпадает с `Directory.Build.props`, рабочее дерево чистое, тега ещё нет,
   `gh` авторизован, файл заметок и ключ подписи на месте.
2. **Сборка и испытания.** `dotnet build SplitVpn.slnx -c Release` без предупреждений и оба тестовых
   исполняемых файла (`dotnet test` в этом окружении запускает ноль тестов).
3. **Установщик.** `scripts\build-installer.ps1 -Version <версия>`; затем `ProductVersion` внутри MSI
   сверяется с выпускаемой версией — это ловит случай «выложили пакет от прошлой сборки».
4. **Манифест `update.json` и подпись к нему.** Манифест собирается строкой с фиксированным порядком
   полей и пишется как UTF-8 без BOM с переводами строк LF: подпись считается по точным байтам файла,
   поэтому он никогда не пересериализуется. Подписывает и тут же проверяет `splitvpn-cli`— тем же
   кодом, что и служба, так что разойтись форматы не могут.
5. **Снимок исходников.** Один коммит без истории в ветку `publish` и `push --force-with-lease` в
   `main` на GitHub. Приватная история `main` не публикуется: в ней остаются адреса серверов и
   внутренние имена. Манифест добавляется только во временный индекс снимка — рабочее дерево и
   история не меняются.
6. **Релиз.** `gh release create v<версия>` с тремя активами: MSI, `update.json`, `update.json.sig`.
   В заметки дописываются SHA-256 установщика и предупреждение об отсутствии подписи Authenticode.
7. **Проверка выложенного.** Манифест скачивается обратно по адресу последнего выпуска, проверяется
   подпись, сверяются версия и размер установщика.

`-DryRun` доводит дело до снимка и не отправляет ничего наружу. `-SkipBuild` берёт уже собранный MSI.

## Ключ подписи выпусков

Установщик не подписан Authenticode, поэтому подлинность обновления держится на подписи манифеста:
скачанному по HTTPS доверять нельзя — подложный корневой сертификат в хранилище машины делает
перехват незаметным, а программа рассчитана на работу под блокировками.

- Алгоритм — ECDSA P-256 / SHA-256, формат подписи **IEEE P1363** (64 байта), задан явно и в
  `UpdateManifestVerifier`, и в команде подписи.
- Закрытый ключ — зашифрованный PKCS#8 в `%USERPROFILE%\.splitvpn\release-signing.pem`,
  пароль рядом в `release-signing.password.txt`; каталог закрыт правами только для владельца.
  **Сделайте копию обоих файлов вне этого компьютера.** Без ключа ни одна установленная копия
  программы не примет новый выпуск.
- Открытый ключ зашит в `src\SplitVpn.Core\Update\UpdateTrust.cs` — словарём по идентификатору
  `kid` из манифеста.

Создать новый ключ:

```powershell
splitvpn-cli release-keygen --out %USERPROFILE%\.splitvpn\release-signing.pem --kid sv-2027-01
```

Команда печатает строку для `UpdateTrust.PublicKeys`.

**Смена ключа** идёт через промежуточную версию: сначала выпускается версия, знающая и старый, и
новый ключ (оба в словаре), подписанная **старым**; после того как пользователи на неё обновятся,
следующий выпуск подписывается новым, а старый убирается из словаря. Если выбросить старый ключ
сразу, обновление не примут те, кто ещё не поставил промежуточную версию.

## Заметки к выпуску

На русском, обязательно: что нового, состав и протоколы, требование закрыть `SplitVpn.exe` перед
установкой поверх, команда `msiexec`. SHA-256 и предупреждение о неподписанном установщике скрипт
дописывает сам — в файле заметок их дублировать не нужно.

**Первый абзац файла заметок идёт в манифест** и показывается в карточке «О программе» перед
установкой: напишите его как короткую сводку выпуска (до 600 знаков). Остальной текст уходит только
на страницу выпуска. Файл читается как UTF-8 независимо от наличия BOM.

## Почему не GitHub Actions

Сборка MSI требует нативных библиотек AnyConnect, которых в git нет: их собирает
`scripts\build-openconnect.sh` под MSYS2 из закреплённых по SHA-256 исходников и пакетов. На чистом
раннере это десятки минут на каждый прогон, а версии пакетов pacman со временем уезжают — сборка
начнёт падать на каждом выпуске, пока хеши не обновят вручную. Кроме того, закрытый ключ подписи
пришлось бы хранить секретом репозитория: тогда компрометация учётной записи GitHub давала бы и
право выложить релиз, и ключ, которым он подписан, — то есть обесценивала бы саму подпись.
Локальная сборка уже настроена и воспроизводима по хешам.
