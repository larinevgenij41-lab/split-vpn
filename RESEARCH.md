# Готовые проекты маршрутизации и обновляемые базы

Проверено 2026-09-12. Дополнение к [функциональному плану](PLAN.md). Исследованы официальные репозитории и документация, выполнено пробное чтение трёх публичных баз. Приложения не запускались, маршруты не изменялись; совместимость с конкретным SSTP-сервером не проверена.

## Предлагаемое решение

Для первой версии: встроенный SSTP Windows + управление системными маршрутами + готовая RU-база Loyalsoldier/geoip с автоматическим обновлением. Из VpnDialerPlus изучить и при необходимости адаптировать небольшие части взаимодействия с Windows VPN и маршрутами. Решение о переносе конкретных фрагментов — после чтения исходников и проверки на Windows 11.

sing-box оставить альтернативным движком для будущих сложных правил. Его включение в основной тракт требует прототипа совместной работы с RAS-интерфейсом. Готового проверенного приложения, которое без доработок выполняет весь наш набор требований SSTP + Россия напрямую + автоматические базы + защита при сбоях, в просмотренных источниках не установлено.

### Вариант с sing-box

Документация содержит удалённые наборы правил, интервал обновления и кеш, а также привязку исходящих соединений к интерфейсу. [Remote rule-set](https://sing-box.sagernet.org/configuration/rule-set/), [bind_interface](https://sing-box.sagernet.org/configuration/shared/dial/).

Возможная схема для проверки: Windows устанавливает SSTP; sing-box принимает трафик через TUN; RU отправляет через физический интерфейс, остальное — через RAS-интерфейс. Это проектная гипотеза, а не проверенная совместимость: необходимо проверить циклы маршрутизации, поведение при исчезновении интерфейса, UDP/ICMP, DNS и IPv6. Список протоколов: [outbound sing-box](https://sing-box.sagernet.org/configuration/outbound/).

Перед интеграцией фиксировать стабильную версию: текущая онлайн-документация может описывать поля более новой версии. Проверять LICENSE выбранного коммита и условия распространения. Встроенный загрузчик sing-box не заменяет наши проверки качества базы, журнал системных изменений и защиту SSTP.

Репозиторий указывает CC-BY-SA-4.0 и GPL-3.0, содержит атрибуцию MaxMind; до поставки зафиксировать применимые условия данных и кода |

| [IPdeny](https://www.ipdeny.com/ipblocks/) | Готовые агрегированные CIDR, IPv4 и IPv6; на проверенной странице дата обновления 2026-09-11 | Альтернатива для режима регистрации сетей. Проверять условия использования и частоту запросов поставщика |
| [DB-IP Country Lite](https://db-ip.com/db/download/ip-to-country-lite) | CSV/MMDB, ежемесячные выпуски, CC BY 4.0 с атрибуцией | Геолокационная альтернатива: потребуется извлечение RU и преобразование диапазонов |
| [MaxMind GeoLite](https://dev.maxmind.com/geoip/geolite2-free-geolocation-data/) | Официальные геобазы и механизм получения | Прямой источник при необходимости; отдельная настройка доступа и проверка условий поставки |

IPdeny описывает основу как выделения региональных регистраторов. Даже более подробный ipverse/geo-ip-blocks основан на регистрационных записях и прямо предупреждает о несовпадении с реальным местом работы сетей. [Основа IPdeny](https://www.ipdeny.com/about.php), [описание ipverse/geo-ip-blocks](https://github.com/ipverse/geo-ip-blocks).

Ещё один вариант преобразования — [v2fly/geoip](https://github.com/v2fly/geoip): CLI читает GeoIP-форматы и умеет выводить текст CIDR; проект описывает ежемесячные публикации. Для готового RU-текста в первой версии дополнительный конвертер не нужен.

Не объединять разные базы автоматически по принципу «всё, что хотя бы один источник назвал Россией»: это расширяет прямой доступ и меняет политику. Источник выбирается явно. Резервный сервер скачивания должен раздавать ту же версию той же базы; иной поставщик — отдельная смена источника с просмотром различий.

## Автоматическое скачивание в приложении

Автообновление включено по умолчанию и входит в первую версию. Приложение загружает данные; никакие скачанные скрипты не исполняются.

### Настройки пользователя

- Источник: «GeoIP — рекомендованный», «Страна регистрации — ipverse/IPdeny», расширенная настройка собственного HTTPS-источника.
- Переключатель автоматического обновления; интервал по умолчанию 24 часа, выбор 1/3/7 дней с учётом ограничений поставщика.
- Кнопки «Проверить сейчас», «Импортировать файл», «Вернуть предыдущую базу».
- Источник и версия базы, время последней проверки отдельно от времени изменения данных, следующая проверка.
- Количество IPv4/IPv6-сетей, результат обновления, число добавленных и удалённых диапазонов.
- Настройка скачивания в лимитной сети; по умолчанию отложить фоновое обновление, ручное скачивание доступно.
- Настройки зеркала той же базы и ручного URL находятся в расширенном разделе.

### Порядок работы загрузчика

1. При первом запуске получить базу. Если она недоступна, возможен временный режим всего интернета через VPN или импорт файла. Подключение SSTP не должно зависеть от наличия RU-базы.
2. Проверять срок обновления при запуске службы, по расписанию и после восстановления сети. Один активный запрос на источник; случайный сдвиг времени и увеличение задержки после ошибок.
3. Использовать HTTPS с проверкой сертификата, таймаутами и ограничением размера ответа. Использовать ETag/Last-Modified, когда их предоставляет источник; HTTP 304 не считать новой версией базы.
4. Если поставщик поддерживает версии/коммиты, сначала определить конкретную ревизию, затем получить файлы этой ревизии. Не собирать IPv4 и IPv6 из разных состояний движущейся ветки.
5. Сохранить ответ во временный файл, проверить формат, префиксы и границы сетей, семейства адресов, дубликаты, перекрытия и специальные диапазоны. Отклонять HTML-страницы вместо списка, пустой RU-набор и неожиданный маршрут 0.0.0.0/0 или ::/0.
6. Посчитать SHA-256 для идентификации содержимого, проверить опубликованную контрольную сумму при наличии. Подпись проверять при использовании нашего подписанного канала. Хеш сам по себе не подтверждает подлинность стороннего файла.
7. Сравнить с текущей базой. Резкие изменения состава или суммарного покрытия адресов направлять на ручное рассмотрение; пороги определяются на истории выбранного источника. До решения сохранять рабочую версию.
8. Скомпилировать новую политику совместно с ручными исключениями. При активном туннеле сначала ограничить изменяемые направления, обновить маршруты и фильтры, проверить результат, затем снять временные ограничения.
9. После успешного применения атомарно переключить указатель активной версии данных; сохранить предыдущие версии. Между изменениями таблиц маршрутов и WFP нет единой транзакции, поэтому сетевое применение требует журнала и компенсирующих действий.
10. При ошибке вернуть предыдущую политику, записать причину и назначить повторную попытку. Не снимать защиту и не удалять последнюю рабочую базу.

При включённой защите скачивание идёт через VPN; не добавлять постоянное разрешение прямого доступа ко всему GitHub или CDN. При первой загрузке можно сначала поднять SSTP в режиме всего интернета через VPN. Если пользователь ещё не активировал защиту, первый мастер может использовать обычное подключение с явным состоянием в UI.

Дополнительные испытания: HTTP 304/404/429, таймаут, разрыв загрузки, плохой сертификат, повреждённый файл, HTML вместо списка, исчезновение зеркала, отсутствие базы при первом запуске, прерывание применения маршрутов, перезагрузка во время обновления, конфликт с ручным правилом. Результат каждого сбоя — рабочая старая политика либо явно показанный защищённый режим.

## Следующий шаг реализации

На сетевом прототипе прочитать релевантные исходники VPN Dialer+, закрепить исходные версии и лицензии, подключиться к тестовому SSTP и применить реальный RU-набор. Замерить маршруты/WFP и проверить обрыв. Только если системный вариант не удовлетворит измеренным требованиям или понадобятся сложные правила, прототипировать вариант с sing-box.
